# D-03 Simulator launcher socket drops connections under a modest burst

- Severity: Low
- Component: teecustody-sim `launcher.py` (listen backlog / accept loop)
- Violates: none directly (robustness of the dev/CI tool, NFR-11 simulator-first CI)
- Found by: QA exploratory, INC-1

## Reproduction
1. Start `teecustody-sim serve ... --socket /tmp/x/s.sock`.
2. From 100 threads at once, connect to the socket and POST a valid `/v1/token` request.

## Expected
All 100 requests are answered (or the client receives an explicit busy response).

## Actual
Several clients fail at `connect()` with `BlockingIOError: EAGAIN` (listen backlog full). Sequential and moderate use is fine;
stalled connections are bounded (reset beyond the cap, recovery after close, slow-header peers closed after about 8 s).
Real workloads make one request per refresh, so impact is limited to stress CI.
