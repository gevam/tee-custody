Tooling decisions (fixed):
- Root `pyproject.toml` is a non-package workspace project (`[tool.uv] package = false`) whose dependencies are
  the two workspace members, so `uv run …` from a clean checkout installs both editable plus the `dev`
  dependency group: `pytest`, `pytest-cov`, `ruff`, `mypy`, `hypothesis`. Build backend `hatchling`.
- Runtime deps, exact `==` pins: `teecustody` → `cryptography`, `cbor2`; `teecustody-sim` → `teecustody`
  (workspace source), `cryptography`. No other runtime dependency. All dev deps also `==`.
- `teecustody-sim` console script: `teecustody-sim = "teecustody_sim.cli:main"`.
- Ruff: line length 100, target `py312`, rules `E,W,F,I,B,UP,S,TID,PT,SIM,RUF,ANN,BLE,T20`;
  `isort.known-first-party = ["teecustody", "teecustody_sim"]`; `**/tests/**`, `tests/**` and
  `spec/vectors/**` ignore `S101,S105,S106,ANN`; `extend-exclude` `.semgrep`, `node_modules`. The Tech
  Lead's contract tests under `tests/integration/contracts/` already pass this configuration.
  `packages/teecustody-py/ruff.toml` (extends root) bans via TID251: `cbor2` ("use teecustody.wire", SR-3),
  `http.server`, `socketserver` ("no inbound listener", NFR-2), `teecustody_sim` (NFR-6); `src/teecustody/wire/cbor.py`
  and `tests/**` are exempt from TID251. `packages/teecustody-sim/ruff.toml` bans `cbor2`.
- mypy strict, `python_version = "3.12"`; if `cbor2` ships no type information, one override
  `ignore_missing_imports` for `cbor2.*` only.
- pytest: `addopts = "--import-mode=importlib"`, `filterwarnings = ["error"]`.
- coverage: `branch = true`, `fail_under = 80`, `exclude_also = ["if TYPE_CHECKING:", "@overload"]`.

## Acceptance criteria (each becomes a test, in this order)
1. Given the stubs, when `test_api_surface.py` imports `teecustody.attest`, `teecustody.channel`,
   `teecustody.wire`, `teecustody.obs`, `teecustody_sim`, then every name in API.md §B/§C is importable from
   those package roots.
2. Given each stub function/method, when called with valid-typed arguments, then it raises
   `NotImplementedError` whose message is exactly its owning task id.
3. Given the final files, when inspected, then every constant, enum value, dataclass default and
   `NEGATIVE_CASES` row equals API.md (compare against literals written in the test).
4. Given `LauncherError(LauncherErrorCode.TOKEN_REJECTED)`, `WireError(...)`, `SimConfigError(...)`, when
   `str()` is taken, then it equals the code value only.
5. Given `AttestationToken(value="SENTINEL", issued_at=1, expires_at=2)`, when `repr()` is taken, then
   `SENTINEL` is absent.
6. Given `importlib.metadata.requires("teecustody")`, then no requirement names `teecustody-sim` (NFR-6).
7. Given source text `import cbor2` / `import http.server` / `import socketserver` / `import teecustody_sim`
   linted with `ruff check --stdin-filename packages/teecustody-py/src/teecustody/attest/x.py -`, then ruff
   exits non-zero with TID251; `import cbor2` at `packages/teecustody-py/src/teecustody/wire/cbor.py` and at
   `packages/teecustody-sim/src/teecustody_sim/x.py` behave as the policy above states (`test_lint_policy.py`).
8. Given a clean clone, when `uv run pytest -q packages/teecustody-py packages/teecustody-sim`,
   `uv run ruff check .`, `uv run ruff format --check .`,
   `uv run mypy --strict packages/teecustody-py/src packages/teecustody-sim/src` and
   `uv run pytest --cov=teecustody --cov-report=term-missing packages/teecustody-py` run, then each exits 0.
9. Given `git check-ignore .teecustody-sim/x`, then it reports the path ignored.
