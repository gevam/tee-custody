## Interface contract
`spec/wire/README.md` states, verbatim, these rules (numbered as here):
1. Encoding is RFC 8949 §4.2.1 Core Deterministic Encoding: shortest-form arguments for integers and lengths,
   definite lengths only, map keys ordered by the bytewise lexicographic order of their encoded form.
2. Permitted data items only: unsigned and negative integers in [−2^64, 2^64−1]; byte strings; UTF-8 text
   strings; arrays; maps whose keys are all text strings; `false`, `true`, `null`. Forbidden: tags, floats,
   `undefined`, other simple values, indefinite lengths.
3. No duplicate map keys. Exactly one top-level data item; no trailing bytes.
4. A decoder checks input length against its limit before parsing, scans the item structure left to right,
   materialises the value, re-encodes it under rule 1 and requires byte equality. There is no permissive fallback.
5. Error categories (first violation in byte order wins; key order and duplicates are evaluated when a map
   ends): `TOO_LARGE` input longer than `max_bytes`; `MALFORMED` truncated, trailing bytes, invalid UTF-8,
   reserved additional-information 28–30, additional information 31 on major type 0, 1 or 6, two-byte simple
   value below 32, stray break, empty input; `NONCANONICAL` non-shortest argument, indefinite length, unsorted
   or duplicate keys; `UNSUPPORTED_TYPE` tag, float (any value), `undefined`, other simple value, non-text map
   key; `LIMIT_EXCEEDED` depth > `max_depth` (top-level item has depth 1; every array element, map key and map
   value has its container's depth + 1) or total data items > `max_items` (every map key and every map value
   counts 1).
   Per data-item header the checks run in this order: (a) additional information 28–30 on any major type, 31 on
   major type 0, 1 or 6, or 31 on major type 7 (a break; every break is stray because indefinite lengths fail
   at (d)) → `MALFORMED`; (b) argument bytes missing, or major type 7 with additional information 24 and
   argument < 32 → `MALFORMED`; (c) major types 0–6 only: non-shortest argument → `NONCANONICAL`; (d) indefinite
   length → `NONCANONICAL`, tag / float (major type 7, additional information 25–27, whatever the value) /
   `undefined` / other simple value → `UNSUPPORTED_TYPE`, a map key that is not a text string →
   `UNSUPPORTED_TYPE`; (e) item depth > `max_depth` → `LIMIT_EXCEEDED`; (f) array/map: items so far (headers
   read, including this one) + declared children (maps: 2 × count, computed without overflow) > `max_items` →
   `LIMIT_EXCEEDED`, then declared children > remaining input bytes → `MALFORMED`; byte/text string: declared
   length > remaining bytes → `MALFORMED`, then invalid UTF-8 → `MALFORMED`. No buffer is allocated for a
   declared length or count before (f) passes (ADR 0010 allocation guard).
6. `proto` = `"tee-chan-v1"` (spec §5.3 step 8). A wire change updates the CDDL, bumps `proto` and regenerates
   `spec/vectors` in the same change (PROJECT.md §5, NFR-7).

## Acceptance criteria (each becomes a test, in this order)
1. (`test_canonical_cbor.py`) Given each valid case, when `teecustody.wire.decode(bytes, DecodeLimits(**limits))`
   then `encode(value)`, then the bytes are identical; given each invalid case, `WireError` with that `error`.
2. Given the JSON file, ids are unique and every `error` is one of the five codes.
3. (`test_attestation_suite.py`) Given `spec/vectors/attestation/suite.cbor`, when decoded with
   `DecodeLimits(1_048_576, 8, 16_384)`, then it re-encodes to identical bytes and has exactly the CDDL keys
   and fixed values; `verify_at_ms == generated_at * 1000`.
4. Given the suite, case ids equal API.md §G ids in order, and each case's `expect`, `check`, `error_code`,
   `altered`, `debug_event` equal §G (table hard-coded in the test, not imported from `teecustody_sim`).
5. Given each case token, its JWS payload differs from case `valid`'s payload exactly at the `altered` dotted
   paths (recurse into objects; compare arrays whole); `alg_none` and `token_signature_corrupted` payloads equal `valid`'s.
6. Given case `valid`, its `eat_nonce` equals lowercase hex SHA-256 of `identity_public_key`.
7. Given `profile_json` / `production_profile_json`, each is a JSON object with exactly API.md §E keys;
   `profile_kind` is `development` / `production`; the production `issuer` is
   `https://confidentialcomputing.googleapis.com`; every `signer_keys` entry has exactly `key_id`, `algorithm`.
8. (`test_differential_corpus.py`) Given `spec/vectors/wire/differential-corpus.json`, it has the API.md §F
   shape, ≥ 500 cases with unique ids, and for every case `teecustody.wire.decode(bytes, limits)` yields the
   recorded `outcome` (`accept`, or the `WireError` code); for every case recorded `accept`,
   `encode(decode(bytes, limits)) == bytes` (asserted in the harness, independent of the codec's internal check).
9. [2026-10-01] Given each integer field the harness reads — `canonical-cbor.json` `version` and every `limits`
   value; corpus `version`, `seed` and every `limits` value; suite `suite_version`, `generated_at`,
   `verify_at_ms` — it passes `require_int(value)` (a helper in `conftest.py`: `type(value) is int`, else the
   test fails) before any equality comparison, so `True` and `1024.0` are rejected although `True == 1` and
   `1024.0 == 1024`. A unit test in `test_canonical_cbor.py` shows `require_int` failing on `True`, `False`,
   `1.0`, `1024.0` and passing on `1`.

- NFR-7: criteria 3–6 make the suite a shared oracle; the harness asserts the suite, not the simulator code.
