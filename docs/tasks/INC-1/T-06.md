## Goal
The workload generates its identity key, derives `H(IK_pub)`, obtains an audience- and nonce-bound token from
the launcher Unix socket, and keeps a valid token by refreshing before expiry — through exactly one launcher
client, with no listener and no other token source.

## Interface contract
API.md §B `attest/*`, `channel/identity.py` (implements); `attest/ports.py`, `obs/types.py` (consumes).
ARCHITECTURE "Attestation and launcher" (verbatim): "`identity_nonce` is the normative hash of the workload
public identity key … `AttestationToken` is an opaque signed-token string plus locally parsed `issued_at` and
`expires_at` metadata; parsed claims are untrusted until client verification. Startup fails if a token cannot
be obtained. Refresh occurs before expiry using the normative/configured refresh parameters; refresh failure does
not replace a still-valid token with an unverified token. The launcher adapter opens only the platform-provided
socket and does not bind a listener."
Spec §5.1 step 2 (verbatim): "Request an attestation token from the Confidential Space launcher (Unix socket)
with audience `AUDIENCE` and a custom nonce equal to `H(IK_pub)` in the encoding the launcher requires. The
client MUST use the same encoding when comparing. The default token file, which carries no custom nonce, MUST NOT
be used for this purpose." §5.1 step 4: "… a freshly requested token (same nonce, same IK) whenever the token
approaches expiry …". §11: "request tokens only through the launcher socket with the custom nonce (§5.1). Never
accept a token from any other source. The workload has exactly one launcher client and no environment
detection". "**No inbound ports.** The container exposes nothing."
Derived values: API.md §A (identity nonce = SHA-256 of raw 32-byte Ed25519 key; launcher nonce = lowercase hex).
Wire facts: FACTS F-01, F-02, F-03, F-05.

Behaviour (fixed):
- `IdentityKey`: Ed25519 via `cryptography`; `public_bytes()` raw 32 bytes; `repr` `IdentityKey(<redacted>)`.
- `ConfidentialSpaceLauncher.get_attestation_token`: local validation first — `token_type != "OIDC"`,
  `len(identity_nonce) != 32`, or `audience` empty / > 2048 chars → `INVALID_CONFIGURATION`, no connection
  made. Then HTTP/1.1 over `AF_UNIX` (`http.client.HTTPConnection` subclass whose `connect` opens the socket,
  `timeout_s`): `POST /v1/token`, `Content-Type: application/json`, body
  `{"audience": a, "nonces": [launcher_nonce], "token_type": "OIDC"}`. Missing socket, refused, timeout,
  `OSError`, status ≥ 500 → `UNAVAILABLE`; status 4xx or other non-200, body > `max_response_bytes` (read at most
  `max_response_bytes + 1`), non-UTF-8 → `TOKEN_REJECTED`; 200 → `parse_token_metadata(body, audience=a,
  expected_nonce=launcher_nonce, max_token_bytes=max_response_bytes)`.
- `parse_token_metadata`: `TOKEN_REJECTED` unless: UTF-8 length ≤ max; exactly three `.`-separated segments;
  payload segment strict base64url (no padding) decoding to a JSON object; `iat`, `exp` are `int` (not `bool`)
  with `exp > iat`; `aud == audience`; `eat_nonce == expected_nonce` or `== [expected_nonce]` (F-05). No
  signature verification (untrusted metadata).
- `AttestationLifecycle`: constructor → `ValueError` if `refresh_margin_s < 1` or key length ≠ 32.
  `start()` calls the launcher once with `identity_nonce(identity_public_key)`; success logs
  `ATTESTATION_TOKEN_OBTAINED`; failure logs `ATTESTATION_TOKEN_FAILED` and re-raises. `current()` before a
  successful `start()` → `RuntimeError("NOT_STARTED")`. `refresh_if_due()`: `NOT_DUE` (no call) when
  `clock() < expires_at - refresh_margin_s`; otherwise request with the same nonce: success → `REFRESHED`, logs
  `ATTESTATION_TOKEN_REFRESHED`; failure while `clock() < expires_at` → `FAILED_KEPT_CURRENT`, logs
  `ATTESTATION_REFRESH_FAILED`; failure at/after `expires_at` → logs `ATTESTATION_TOKEN_EXPIRED` and re-raises.
  Log calls carry no fields.

## Acceptance criteria (each becomes a test, in this order)
1. Given `IdentityKey.generate()` twice, `public_bytes()` are 32 bytes and differ; `repr` contains no key bytes.
2. Given a 32-byte key, `identity_nonce` = `hashlib.sha256(key).digest()`; `launcher_nonce` is 64 lowercase
   hex chars; wrong lengths → the API.md `ValueError`s.
3. Given a fake launcher (`socketserver.UnixStreamServer` in the test on a short temp path), when a token is
   requested, then it received exactly F-02's method, path, content type and JSON body.
4. Given each failure class in "Behaviour", the stated `LauncherErrorCode`; `str(err)` is the code only.
5. Given each `parse_token_metadata` rejection rule, `TOKEN_REJECTED`; given a well-formed token,
   `issued_at`/`expires_at` equal its claims.
6. Given the lifecycle and a scripted fake `Launcher` + fake clock, each `refresh_if_due` outcome above occurs
   at its boundary (`expires_at - margin - 1`, `expires_at - margin`, `expires_at - 1`, `expires_at`), and every
   request used the nonce from `start()`.
7. Given `socket.socket.bind` and `socket.socket.listen` monkeypatched to raise, `start()` and a refresh
   against the fake socket launcher still succeed (NFR-2).
8. Given the source of `teecustody/attest/**` and `teecustody/channel/**`, it contains no
   `attestation_verifier_claims_token`, `.bind(`, `.listen(` or `os.environ` (`test_source_policy.py`).
9. Given captured logs during success and failure, the token value and nonce never appear.
10. FACTS F-01, F-02, F-03, F-05 re-confirmed against V-01's URLs; URL + access date in the Task Report.
