## Goal
Without cloud credentials, the simulator serves OIDC discovery and JWKS on loopback and the Confidential Space
token endpoint on a Unix socket, writes the default token file, enforces `SIGNERS_REQUIRED` and the §15.5
separation rules before binding anything, and records its state for the CLI.

## Interface contract
API.md §C `issuer.py`, `launcher.py`, `simulator.py`, `sim-state.json` (implements); `config.py`,
`constants.py`, `keys.py`, `token.py` (consumes). ARCHITECTURE "Attestation and launcher" (verbatim, 2026-09-30):
"`GET /.well-known/openid-configuration` returns `issuer` (`SIM_ISSUER`), `jwks_uri`, and signing metadata,
which is `RS256` only." "`GET /jwks` returns only the public half of the simulator's **token-signing (issuer)
key** (CI-8). Development image-signer public keys are never served by the issuer. They reach the client only
through the development trust profile's `signer_keys`." "`SIGNERS_REQUIRED` is enforced before startup. Signer
private keys stay in simulator configuration and are never emitted by the CLI, issuer responses, logs, or
vectors."
Spec §15.2 item 1 (verbatim): "A local process that mounts the same Unix socket path the real launcher exposes
and implements the same token endpoint, with the same request schema (`audience`, `nonces`, `token_type`) and the
same constraints on nonce count and length … It also writes the default token file at the same path."
Spec §15.5 (verbatim): "The simulator binds to loopback only. Binding elsewhere requires an explicit flag and
prints a warning on every start." "The simulator environment MUST NOT contain production credentials, production
queue configuration or the production KMS key resource name."
Facts: FACTS F-02, F-03, F-04, F-13.

Behaviour (fixed):
- `IssuerServer` (stdlib `ThreadingHTTPServer`): `GET /.well-known/openid-configuration` → 200
  `application/json` `{"issuer", "jwks_uri": origin + "/jwks", "id_token_signing_alg_values_supported": ["RS256"],
  "response_types_supported": ["id_token"], "subject_types_supported": ["public"], "scopes_supported": ["openid"],
  "claims_supported": ["aud", "dbgstat", "eat_nonce", "exp", "hwmodel", "iat", "iss", "nbf", "secboot",
  "submods", "swname"]}`; `GET /jwks` → 200 the given JWKS; other path → 404; other method → 405;
  request line or headers > `limits.max_request_bytes` → 431; bodies are never read. `origin` =
  `http://<host>:<bound port>` (IPv6 in brackets).
- `LauncherServer` (stdlib `socketserver.ThreadingUnixStreamServer` + `BaseHTTPRequestHandler`, socket mode
  0666 in its directory): only `POST /v1/token` (404/405 otherwise). `Content-Length` required and ≤
  `limits.max_request_bytes` (411/413). Body must be a JSON object with exactly keys `audience` (non-empty str),
  `token_type` (`"OIDC"`), `nonces` (list of str, F-03 limits) → else 400 with body `INVALID_REQUEST`. More than
  `limits.max_concurrent_requests` in flight → 503. Success → 200 `text/plain` body = `mint(audience, nonces)`.
- `Simulator.start()` validates **before** creating any file or socket, raising `SimConfigError`:
  `signers_required ∉ [1, MAX_SIGNERS]` → `INVALID_SIGNERS_REQUIRED`; `issuer_host` not in 127.0.0.0/8, `::1`,
  `localhost` and `allow_non_loopback` false → `NON_LOOPBACK_NOT_ALLOWED`; empty `image_reference`, digest not
  `^sha256:[0-9a-f]{64}$`, duplicate env names or empty audience → `INVALID_LAUNCH_CONFIG`; socket path > 100
  bytes, or socket/token-file parent directory missing → `INVALID_PATH`; port ∉ [0, 65535] → `INVALID_PORT`;
  the "§15.5 environment refusal" rule below fires → `PRODUCTION_CREDENTIALS_PRESENT`. Then: `SimKeys.load_or_create`; start `IssuerServer(issuer=SIM_ISSUER,
  jwks=keys.issuer_jwks())`; `TokenMinter(keys, launch, ttl_s=token_ttl_s, token_max_age_s=DEFAULT_TOKEN_MAX_AGE_S)`;
  `LauncherServer(mint=lambda a, n: minter.mint(a, n, int(clock())))`; write the default token file
  (`mint(DEFAULT_TOKEN_AUDIENCE, [], now)`, mode 0644); write `sim-state.json` (0600). With
  `allow_non_loopback`, log `SIM_NON_LOOPBACK_BIND` (warning, `teecustody.obs.get_logger("sim")`) on every start.
  `stop()` stops both servers and unlinks the socket; idempotent. `simulator.py` imports `SimKeys` and
  `TokenMinter` as module attributes so tests can monkeypatch them.

§15.5 environment refusal (amended 2026-10-01). Inputs: `E` = `environ` (default `os.environ`); `W` =
`config.launch.env` and `config.launch.args`. Refuse with `PRODUCTION_CREDENTIALS_PRESENT` if any of R1–R4 holds:
- **R1 names.** A name in `E` or in `launch.env` equals `GOOGLE_APPLICATION_CREDENTIALS`, `GOOGLE_CREDENTIALS`
  or `GOOGLE_OAUTH_ACCESS_TOKEN`, or starts with `CLOUDSDK_AUTH_` (exact, case-sensitive; presence alone, any
  value, including empty). Other `CLOUDSDK_*` names (e.g. `CLOUDSDK_CORE_PROJECT`) are allowed.
- **R2 KMS.** Any value in `E`, any `launch.env` value or any `launch.args` element contains (`re.search`) a
  match of `projects/[^/\s]+/locations/[^/\s]+/keyRings/[^/\s]+/cryptoKeys/[^/\s]+`. No exemption: the
  simulator's `LocalKeyWrapper` never uses a resource name.
- **R3 Pub/Sub.** Any of those values contains a match (`re.finditer`) of
  `projects/([^/\s]+)/(?:topics|subscriptions)/[^/\s]+` whose group 1 is not `_SIM_QUEUE_PROJECT`. Every match
  in a value must be namespaced; one non-namespaced match refuses. Define in `simulator.py`
  `_SIM_QUEUE_PROJECT: Final = "teecustody-sim.invalid"` (§15.2 item 5 namespace: not a syntactically valid GCP
  project id — `.` without a `domain:` prefix — and `.invalid` is RFC 6761-reserved, so no production topic or
  subscription can carry it).
- **R4 gcloud ADC file.** `os.path.lexists(p)` is true (any file type, including a dangling symlink; the file is
  never opened), where `p` = `E["CLOUDSDK_CONFIG"]/application_default_credentials.json` if `CLOUDSDK_CONFIG` is
  set and non-empty, else `E["HOME"]/.config/gcloud/application_default_credentials.json` if `HOME` is set and
  non-empty, else `Path.home()/.config/gcloud/application_default_credentials.json` (the resolution google-auth
  uses).
Patterns are compiled once, ASCII, case-sensitive. A false positive (e.g. a directory path that matches R3) is
intended: fail closed; the developer unsets the variable. `str(err)` is the code only; the matched name, value
or path never appears in the exception, logs or `sim-state.json`. Tests always pass an explicit `environ` whose
`HOME` is an empty `tmp_path` directory, so a developer's real ADC file never affects the suite.

## Acceptance criteria (each becomes a test, in this order)
1. Given a started `IssuerServer`, discovery and JWKS responses match "Behaviour"; 404/405/431 cases hold; the
   bound address is the configured host.
2. Given a `LauncherServer` with a recording `mint`, a valid request returns 200 and the minted text, and
   `mint` received the audience and nonces; each invalid request class returns its status and never calls `mint`.
3. Given `max_concurrent_requests + 1` simultaneous requests held open by a blocking `mint`, the extra one gets 503.
4. Given each `SimConfigError` condition, `start()` raises that code and no socket, key or state file exists.
4a. Given each case below, `start()` raises `PRODUCTION_CREDENTIALS_PRESENT`, no socket/key/state/token file
   exists, and the offending value is absent from `str(err)` and `caplog`: each R1 name in `E`; each R1 name in
   `launch.env`; an R2 value (plain, and embedded as `//cloudkms.googleapis.com/projects/p/locations/global/
   keyRings/r/cryptoKeys/k/cryptoKeyVersions/1`) in an `E` value, a `launch.env` value and a `launch.args`
   element; an R3 topic and an R3 subscription with project `prod-proj` in each of those three places; one value
   holding a namespaced and a non-namespaced R3 match; R4 via `CLOUDSDK_CONFIG`, via `HOME`, as a dangling
   symlink, and via `Path.home()` (monkeypatched) when `E` has neither. Given instead `CLOUDSDK_CORE_PROJECT`,
   `projects/teecustody-sim.invalid/topics/t`, `projects/p` alone, or `CLOUDSDK_CONFIG` pointing to an empty
   directory while `HOME` holds an ADC file, `start()` succeeds (fakes as in criterion 5).
5. Given a valid config (fakes monkeypatched for `SimKeys`/`TokenMinter`), `start()` serves both endpoints,
   writes the default token file and a `sim-state.json` matching API.md §C; `stop()` removes the socket.
6. Given `allow_non_loopback=True` and host `0.0.0.0`, two consecutive starts each log `SIM_NON_LOOPBACK_BIND`.
7. Given all HTTP responses and logs from criteria 1–6, no PEM, private JWK member or token appears in logs.
8. FACTS F-02, F-03, F-04, F-13 re-confirmed; URL + access date in the Task Report.
