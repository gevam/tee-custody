## Goal
`encodeCanonical` / `decodeCanonical` implement `spec/wire/README.md` byte-for-byte like the Python codec, so
Core can read the simulator's vector suite and hash launch configuration identically. `src/wire/cbor.ts` is the
single decode entry point in Core.

## Interface contract
API.md §D `wire/types.ts` (consumed, final) and:
```ts
export function encodeCanonical(value: CanonicalValue): Bytes;
export function decodeCanonical(data: Bytes, limits: DecodeLimits): CanonicalValue;
```
Normative rules (spec/wire/README.md, T-03), reproduced:
1. RFC 8949 §4.2.1 Core Deterministic Encoding: shortest-form arguments, definite lengths only, map keys in
   bytewise lexicographic order of their encoded form.
2. Permitted: integers in [−2^64, 2^64−1], byte strings, UTF-8 text strings, arrays, maps with text keys only,
   `false`/`true`/`null`. Forbidden: tags, floats, `undefined`, other simple values, indefinite lengths.
3. No duplicate keys; exactly one top-level item; no trailing bytes.
4. Check input length before parsing; scan structure left to right; materialise; re-encode; require byte
   equality. No permissive fallback.
5. `TOO_LARGE` > `maxBytes`; `MALFORMED` truncated / trailing / invalid UTF-8 / additional-info 28–30 /
   additional-info 31 on major type 0, 1, 6 / two-byte simple value < 32 / stray break / empty; `NONCANONICAL`
   non-shortest / indefinite / unsorted / duplicate keys; `UNSUPPORTED_TYPE` tag / float (any value) /
   `undefined` / other simple / non-text key; `LIMIT_EXCEEDED` depth > `maxDepth` (top level = 1; every array
   element, map key and map value = container depth + 1) or items > `maxItems` (each key and value counts 1). First
   violation in byte order wins; key order and duplicates are evaluated when the map ends.
   Per data-item header the checks run in this order (T-03 rule 5): (a) additional information 28–30 (any major
   type), 31 on major type 0, 1 or 6, or 31 on major type 7 (every break is stray) → `MALFORMED`; (b) argument
   bytes missing, or major type 7 with additional information 24 and argument < 32 → `MALFORMED`; (c) major
   types 0–6 only: non-shortest → `NONCANONICAL`; (d) indefinite → `NONCANONICAL`, tag / float (major type 7,
   additional information 25–27, whatever the value) / `undefined` / other simple / non-text map key →
   `UNSUPPORTED_TYPE`; (e) depth > limit → `LIMIT_EXCEEDED`; (f) array/map: items so far (headers read,
   including this one) + declared children (maps 2 × count, computed without overflow) > limit →
   `LIMIT_EXCEEDED`, then declared children > remaining bytes → `MALFORMED`; strings: declared length > remaining
   bytes → `MALFORMED`, then invalid UTF-8 → `MALFORMED`. Nothing is allocated for a declared length or count
   before (f) passes (ADR 0010 allocation guard).

Implementation decisions (fixed) [CI-10, ADR 0010 Accepted]:
- No third-party library: `cbor-x` is not used (it is not in `package.json`, and lint bans it). The codec is a
  single-pass **iterative** (explicit stack, no recursion) decoder that validates and materialises together,
  then re-encodes and compares bytes; and an iterative encoder. Text uses `utf8DecodeStrict`/`utf8Encode`
  from `src/encoding.ts`.
- Value mapping: integers decode to `number` when `Number.isSafeInteger`, else `bigint`; byte strings →
  `Uint8Array` (a copy, not a view of the input); text → `string`; arrays → frozen arrays; maps →
  `ReadonlyMap<string, CanonicalValue>` (never plain objects). The encoder accepts `number` only when
  `Number.isSafeInteger` (else `UNSUPPORTED_TYPE`, including `-0`, `NaN`, `1.5`), `bigint` within the rule-2
  range, `Uint8Array`, `string`, arrays, `Map`/`ReadonlyMap` with string keys; anything else (plain objects,
  `undefined`, `Date`, other typed arrays) → `UNSUPPORTED_TYPE`. Map keys are sorted by encoded bytes before writing.
- Limits that are not positive safe integers → `RangeError("INVALID_LIMITS")` before parsing (same meaning as
  Python's `ValueError("INVALID_LIMITS")`; criterion 9).

## Acceptance criteria (each becomes a test, in this order)
1. Given every `valid` case in `spec/vectors/wire/canonical-cbor.json` (read from the repo in
   `cbor-vectors.test.ts`), decode with the file's limits then `encodeCanonical` → identical bytes; `uint_max`
   decodes to `18446744073709551615n`, `nint_min` to `-18446744073709551616n`, `uint_1000000` to `1000000`.
2. Given every `invalid` case, `WireError` with exactly the listed `code`, and `message === code`.
3. Given `new Map([["b",1],["aa",2]])`, `encodeCanonical` → `a261620162616102`.
4. Given `1.5`, `-0`, `NaN`, `2n ** 64n`, `{a: 1}`, `undefined`, `new Map([[1, 2]])` (cast), `new Uint16Array(1)`,
   `encodeCanonical` → `UNSUPPORTED_TYPE`; `true` → `f5`.
5. Given `"81".repeat(10000) + "00"` with `maxDepth: 16`, `decodeCanonical` → `LIMIT_EXCEEDED` without a
   `RangeError` (no recursion).
6. Given a decoded byte string, mutating the input buffer afterwards does not change the decoded value.
7. (property, ≥ 500 generated values, hand-written generator — no new dependency) `decode(encode(v))` deep-equals
   `v`, and `encode` is deterministic.
8. (property, ≥ 500 random byte arrays ≤ 256) `decodeCanonical` returns or throws `WireError`; nothing else.
9. Given `{ maxBytes: 0, maxDepth: 1, maxItems: 1 }` or `maxDepth: 1.5`, `decodeCanonical` throws
   `RangeError("INVALID_LIMITS")`.
10. Given `9b0000000100000000`, `LIMIT_EXCEEDED`, and `process.memoryUsage().arrayBuffers` grows by < 64 KiB
    during the call (allocation guard); given `590100`, `MALFORMED`.
    [2026-10-01] The same < 64 KiB bound holds for `bb8000000000000000` (`LIMIT_EXCEEDED`; the 2 × count sum must
    not wrap or lose precision — use `bigint` or compare before multiplying) and `5bffffffffffffffff` (`MALFORMED`).
11. Given `1b001fffffffffffff` → `9007199254740991` (number) and `1b0020000000000000` → `9007199254740992n`
    (bigint); encoding `9007199254740992n` and `2n ** 53n - 1n` both succeed and round-trip (SR-3 boundaries).
    [2026-10-01] `1b0020000000000001` → `9007199254740993n` (bigint, not a rounded `number`).
13. [2026-10-01] Given vector `map_proto_key` (`a1695f5f70726f746f5f5f00`), `decodeCanonical` returns a `Map` whose
    only key is the string `"__proto__"` with value `0`, `Object.prototype` is unchanged, and re-encoding yields the
    input bytes.
14. [2026-10-01b, D-020] (`cbor.test.ts`, vector limits) 8-byte arguments are read as full 64-bit values, never
    their low 32 bits: `5b0000000100000000` and `7b0000000100000000` (string declaring 2^32 bytes, no payload) →
    `MALFORMED`; `9b0000000100000000` and `bb0000000100000000` (2^32 items / entries) → `LIMIT_EXCEEDED`. A
    low-32-bit reader would see length/count 0 and return a different code.
12. (`test/wire/cbor-fuzz.test.ts`, SR-3) Mutation fuzz seeded from every `valid` case of
    `canonical-cbor.json`: bit flips, byte insert/delete, truncation, header-byte substitution, deterministic
    PRNG with a fixed seed; case count from env `TEECUSTODY_CBOR_FUZZ_CASES` (default 2,000; T-14's scheduled job
    sets 100,000). Every input either decodes to a value that re-encodes byte-identically or throws `WireError`,
    and each input finishes within 50 ms. Seeding from the differential corpus is added by an INC-2 Wave 0
    amendment once T-18 has committed it (still before any INC-2 untrusted decode, SR-3).
