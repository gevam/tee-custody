# T-10: Implement token parsing, trust-profile parsing and identity-nonce encoding in Core

Increment: INC-1   Wave: 1   Tier: STRONG   Depends on: T-02, V-01

## Goal
Core turns an untrusted compact JWS into a `ParsedToken` and an untrusted `trust-profile.json` value into a
branded, frozen `TrustProfile`, rejecting anything malformed, unknown or mixing development and production
anchors. These are the two input boundaries every §6 check consumes.

## Interface contract
API.md §D (implements): `parseToken(token: string, maxTokenBytes: number): ParsedToken`,
`parseTrustProfile(input: unknown): TrustProfile`, `encodeIdentityNonce(identityNonce: Bytes): string`,
`identityNonceFromPublicKey(crypto, identityPublicKey): Promise<Bytes>`. Consumes `encoding.ts`, `json.ts`,
`attestation/types.ts` (`brandTrustProfile`, errors). Profile JSON: API.md §E. Derived values: API.md §A.
Spec §15.4 (verbatim): "The client's verification is a single code path parameterized by a **trust profile**:
`{ issuer, jwks_origin | pinned_root, expected_audience, allowed_hwmodels, allowed_digests, signer_keys,
signers_required, expected_args_hash, expected_env_hash }`." "Exactly two profiles exist. **Production:** Google
issuer, Google JWKS or root, production signer keys, production digests. **Development:** `SIM_ISSUER`, the
simulator's loopback JWKS origin or root, development signer keys, local digests. The profile is selected at
build time. There is no runtime switch and no flag that disables any check, in either profile."
Spec §10.2: the trust profile "is compiled into the client at build time and MUST NOT be fetched from the server at runtime."
Facts: FACTS F-06, F-07, F-09, F-11.

`parseToken` (all failures `AttestationError("MALFORMED", "token")`): `maxTokenBytes` positive safe integer;
UTF-8 length of `token` ≤ `maxTokenBytes`; exactly three `.`-separated segments; segments 1–2 non-empty,
segment 3 may be empty; segments 1–2 → `base64UrlDecode` → `utf8DecodeStrict` → `JSON.parse` → must be JSON
objects; `signature = base64UrlDecode(seg3)`; `signingInput = utf8Encode(seg1 + "." + seg2)`.

`parseTrustProfile` (failures `TrustProfileError(code, field)`; `field` is the JSON path, `""` for the root):
- Plain object with exactly the 14 §E keys (missing or extra → `INVALID_PROFILE`, field = that key).
- `profile_version === 1`; `profile_kind` ∈ {`production`,`development`}; `token_type === "OIDC"` else
  `UNSUPPORTED_TOKEN_TYPE`.
- Production: `issuer === "https://confidentialcomputing.googleapis.com"`, `discovery_url ===
  "https://confidentialcomputing.googleapis.com/.well-known/openid-configuration"` (F-07); `jwks_origin` is an
  `https:` origin; every `allowed_hwmodels` entry ∈ F-09's verified list.
- Development: `issuer` is an `https:` URL ≠ the Google issuer; `discovery_url` and `jwks_origin` use `http:`
  or `https:` with hostname `127.0.0.1`, `localhost` or `[::1]`.
- Origin form: `new URL(x).origin === x`. `expected_audience`: string, 1–2048 chars. `token_max_age_s`:
  integer 1–86400. `allowed_hwmodels`, `allowed_digests`: non-empty, unique; digests `^sha256:[0-9a-f]{64}$`.
- `signer_keys`: non-empty array of objects with exactly `key_id` (`^[0-9a-f]{64}$`, unique), `algorithm`
  (`"ECDSA_P256_SHA256"` → `UNSUPPORTED_ALGORITHM`; other non-`SignatureAlgorithm` → `INVALID_PROFILE`),
  `spki` (`base64Decode` succeeds, non-empty; stored as `Uint8Array`).
- `signers_required`: integer, 1 ≤ n ≤ `signer_keys.length`. Hashes: `^[0-9a-f]{64}$`.
- Returns `brandTrustProfile(...)`. The source contains no simulator literal (API.md §D note).

`encodeIdentityNonce`: 32 bytes → `hexEncode`; other length → `AttestationError("MALFORMED","nonce")`.
`identityNonceFromPublicKey`: 32-byte key → `crypto.sha256(key)`; other length → same error.

## Acceptance criteria (each becomes a test, in this order)
1. Given a token built with `test/support/jws.ts`, `parseToken` returns header, claims, signature bytes and
   the exact signing input.
2. Given each `parseToken` rejection (size + 1 byte, 2 or 4 segments, empty header, `=` padding, non-JSON,
   JSON array payload, invalid UTF-8), `MALFORMED`/`token`; the error message contains no token text.
3. Given a valid development and a valid production profile object, `parseTrustProfile` returns a frozen,
   branded profile with `spki` as `Uint8Array`.
4. Given each rule above violated one at a time (table-driven), the stated code and field.
5. Given `{..., "skip_verification": true}` (NFR-5), `INVALID_PROFILE` with field `skip_verification`.
6. Given a production profile using a loopback `jwks_origin` or `hwmodel` `SIMULATED`, rejected; given a
   development profile with the Google issuer, rejected (SR-7 separation).
7. Given 32 bytes `00..1f`, `encodeIdentityNonce` → `"000102…1f"`; given 31 bytes, `MALFORMED`/`nonce`.
8. Given `testCrypto()` and a 32-byte key, `identityNonceFromPublicKey` equals Node's SHA-256 of it.
9. FACTS F-07, F-09 re-confirmed; URL + access date in the Task Report.
