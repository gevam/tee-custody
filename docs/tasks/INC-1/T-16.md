## Goal
A developer or CI job drives the whole simulator from one command-line tool: serve the launcher and issuer, run a
local workload image against them, emit a positive or single-alteration token, write the development trust
profile, and regenerate the cross-implementation vectors — with validated arguments and no key material on output.

## Interface contract
API.md §C CLI table, `sim-state.json`, `runtime.py`, `cli.py` (implements); `Simulator`, `SimulatorConfig`,
`LaunchConfig` (T-08), `SimKeys`, `TokenMinter`, `parse_alteration` (T-07), `build_trust_profile`,
`generate_suite` (T-17) (consumes). PROJECT.md §4.2 (verbatim):
```
teecustody-sim up --image <local image> --audience <aud>      run workload under the simulator
teecustody-sim token [--alter <claim>=<value>|--drop <claim>]  emit a token; the only source of negative vectors
teecustody-sim vectors --out spec/vectors/                    regenerate cross-implementation vectors
teecustody-sim profile --out dev-profile.json                 emit the development trust profile
```
Spec §15.2 item 1: the simulated launcher "runs the workload container with plain Docker or Podman." §15.5:
"The simulator binds to loopback only. Binding elsewhere requires an explicit flag and prints a warning on every
start." "The simulator environment MUST NOT contain production credentials …"

Behaviour (fixed):
- `main(argv)`: `argparse`; each subcommand accepts `--state-dir` (default `DEFAULT_STATE_DIR`). Usage errors
  exit 2 (argparse default). Validation failures (`SimConfigError`, `ValueError` from T-07) print only the error
  code line to stderr and exit 2; any other exception prints `INTERNAL` to stderr and exits 1 (no traceback).
- `serve`: builds `LaunchConfig` (`--arg` in order; `--env K=V` split on the first `=`; a missing `=` is a usage
  error), `SimulatorConfig(token_file_path=<socket dir>/DEFAULT_TOKEN_FILE_NAME)`, starts `Simulator`, prints
  `issuer=<origin> discovery=<url> socket=<path>` and flushes, then blocks until SIGINT/SIGTERM and stops.
- `up`: `ContainerRuntime(--runtime, default "docker").image_digest(image)` → `sha256:…`; socket at
  `STATE/launcher/teeserver.sock` (directory created 0755); serves as above; `run_workload(...)`; stops the
  simulator after the container exits; returns the container's exit code.
- `ContainerRuntime.image_digest`: runs `[exe, "image", "inspect", "--format", "{{.Id}}", image]`; output must
  match `^sha256:[0-9a-f]{64}$` else `ValueError("INVALID_LAUNCH_CONFIG")`. `run_workload`: `[exe, "run", "--rm",
  "--network", "none", "-v", f"{launcher_dir}:{CONTAINER_LAUNCHER_DIR}", *("-e", f"{k}={v}" per env), image,
  *args]`; returns its exit code. The subprocess runner is injected (default: `subprocess.run(argv,
  capture_output=False, text=True, check=False)`; argv list only, never a shell). Host environment variables
  are never forwarded.
- `token`: reads `sim-state.json` (absent → `STATE_NOT_INITIALISED`, exit 2), `SimKeys.load_or_create(state,
  signers_required)`, `TokenMinter(keys, launch, ttl_s=token_ttl_s, token_max_age_s=DEFAULT_TOKEN_MAX_AGE_S)`;
  `--alter`/`--drop`/`--case` are a mutually exclusive group parsed with `parse_alteration`; prints the token
  plus `\n`.
- `profile`: reads state; writes `build_trust_profile(discovery_url, jwks_origin, expected_audience=audience,
  launch, signers=keys.signers, signers_required)` as JSON (`indent=2`, `sort_keys=True`) to `--out` (0644).
- `vectors`: `generate_suite(Path(--out))`, prints the returned path.

## Acceptance criteria (each becomes a test, in this order)
1. Given `token --audience A --nonce <64 hex>` after a `Simulator` (T-08) wrote the state dir, stdout is one
   JWS whose payload `aud` is `A` and `eat_nonce` the nonce; exit 0.
2. Given `token --case dbgstat_enabled` / `--alter secboot=false` / `--drop eat_nonce`, the payload reflects it;
   combining two of them exits 2.
3. Given `token` with no state dir, stderr is exactly `STATE_NOT_INITIALISED\n`, exit 2.
4. Given `--case nope`, `--nonce short`, `--env NOEQUALS`, exit 2 with a single-line code on stderr.
5. Given `profile --out f` (with `build_trust_profile` monkeypatched to a recorder), the recorder got the state's
   values and `f` holds its JSON.
6. Given `vectors --out d` (with `generate_suite` monkeypatched), it was called with `Path(d)` and stdout is the path.
7. Given `up` with a fake runner, the exact `inspect` and `run` argv above were issued, env values came only from
   `--env`, and the exit code propagates; a bad `inspect` output exits 2.
8. Given `serve` in a thread with a signal simulated by the test, the stdout line appears, a launcher request
   succeeds, and the socket is removed after stop.
9. Given every subcommand's stdout and stderr in criteria 1–8, neither contains `PRIVATE KEY` nor any private
   JWK member name; an unexpected exception prints only `INTERNAL`.
