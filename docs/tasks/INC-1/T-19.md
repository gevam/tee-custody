## Goal
Make the simulator's §15.5 production-configuration refusal impossible to bypass by putting a namespaced queue
name first in a delimited, JSON or URL-encoded value. Make the launcher/issuer slot release deterministic, so
the slot tests stop flaking.

## Interface contract
Unchanged: API.md §C `Simulator`, `SimulatorConfig`, `LaunchConfig`, `SimConfigErrorCode`. The T-08 rule is
"§15.5 environment refusal (amended 2026-10-01)" in T-08.md. Its R1 and R4 are unchanged. **For R2 and R3, the
text below replaces how T-08 says values are matched.**

**Candidates.** For each inspected value `v` (every value in `E`, every `launch.env` value, every
`launch.args` element), the candidate set `C(v)` is the smallest set built as follows:
1. `v` is in `C(v)`.
2. If `c` is in `C(v)` and contains `%`, then `urllib.parse.unquote(c)` is in `C(v)`. Decode once only, so
   `unquote` is not reapplied to its own output.
2a. (amended 2026-10-05) If `c` is in `C(v)` and contains `\`, `_json_unescape(c)` is in `C(v)`. That
   function makes one left-to-right pass of `\\(?:u([0-9a-fA-F]{4})|(["\\/bfnrt]))` over the whole text,
   decoding escapes wherever they appear. Each chain from `v` (or from a JSON-reached string) applies step 2
   at most once and step 2a at most once, in either order. Neither decoding is reapplied to its own output.
3. If `c` is in `C(v)` and `json.loads(c)` succeeds, every `str` reachable in the result is in `C(v)`. Each such
   string starts a fresh chain (steps 2, 2a and 3). This covers array elements, object keys and object values
   at any depth. Numbers, booleans and `null` add nothing. `json.JSONDecodeError` means the candidate is not
   JSON. Any other `ValueError` (a parser limit, e.g. integer digits) or a `RecursionError` refuses.
4. (amended 2026-10-05; SR-4 for start-up) **Dedupe and budget, per inspected value.** Work items are
   `(text, may_unquote, may_unescape)`. Keep a `seen` set and never queue an item already in it. Count every
   item that is examined (matched or parsed). Refuse with `PRODUCTION_CREDENTIALS_PRESENT` (fail closed) when
   the value's examined items exceed `_MAX_CANDIDATES: Final = 1024`, or their summed `len(text)` exceeds
   `_MAX_CANDIDATE_CHARS: Final = 1_048_576`. Check both limits before examining each item.

**Matching.** Refuse with `PRODUCTION_CREDENTIALS_PRESENT` if any candidate:
- R2: matches `projects/[^/\s]+/locations/[^/\s]+/keyRings/[^/\s]+/cryptoKeys/[^/\s]+` (`re.search`); or
- R3: has a match of `(?=projects/([^/\s]+)/(?:topics|subscriptions)/[^/\s])` (`re.finditer`, ASCII) whose
  group 1 ≠ `_SIM_QUEUE_PROJECT`.

The R3 pattern is a zero-width lookahead, so every occurrence of `projects/` is tested independently. A
namespaced name can no longer absorb a following production name, whatever the delimiter (`,`, `;`,
whitespace, `&`, `"`, `)`, …). No splitting on fixed delimiters is needed.

**Documented limits (not requirements; do not try to detect):** a name split across variables or arguments
(e.g. `PROJECT=prod` with `TOPIC=t`); base64 or any other encoding besides percent-encoding and JSON escapes;
double percent-encoding; names the workload builds at runtime. Record these limits in the `simulator.py`
docstring for `_production_configuration_present`.

**Slot ordering.** In `_BoundedServer._serve_one`, the `finally` block is `try: slot.release()` `finally:
self.shutdown_request(request)`. The slot is released after the handler returns (response flushed) and before
the connection is shut down. A client that has seen EOF is therefore guaranteed that the slot is free. Update the
docstring to say so. The thread bound becomes "≤ 2 × `max_concurrent_requests` threads holding slots, plus
threads that have released their slot and are only closing their connection".

## Acceptance criteria (each becomes a test, in this order)
1. Given each value below as an `E` value, a `launch.env` value and a `launch.args` element, `start()` raises
   `PRODUCTION_CREDENTIALS_PRESENT`, creates no file or socket, and the value is in neither `str(err)` nor
   `caplog`. `S` = `projects/teecustody-sim.invalid/topics/a` and `P` = `projects/prod-proj/topics/b`:
   (The values below are the literal text of the value. `\t` and `\n` are the tab and newline characters. JSON
   escapes such as `\/`, `\u002f`, `\"` and `\\/` are literal characters in the value.) `S,P`; `S;P`; `S P`; `S\tP`; `S\nP`; `?x=S&y=P`; `["S","P"]`; `{"k":{"n":["S",{"P":1}]}}` (P as a key);
   `["projects\/prod-proj\/topics\/b"]`; `["projects/prod-proj/subscriptions/b"]`;
   `{"c":"[\"projects\\/prod-proj\\/topics\\/b\"]"}` (JSON in a JSON string);
   `projects%2Fprod-proj%2Ftopics%2Fb`; `["projects\/p\/locations\/l\/keyRings\/r\/cryptoKeys\/k"]`;
   `projects%2Fp%2Flocations%2Fl%2FkeyRings%2Fr%2FcryptoKeys%2Fk`; `"[" * 100_000 + "]" * 100_000`.
1a. (amended 2026-10-05) The refusal set of criterion 1 also covers:
   - `projects\/prod-proj\/topics\/b` outside JSON (step 2a);
   - the two escaped-name combinations the Code Reviewer listed as unpinned in round 2, each in an `E` value, a
     `launch.env` value and a `launch.args` element.
1b. (amended 2026-10-05) Budget and dedupe:
   - Given the Security Reviewer's input built to 2 KB and to 64 KB, `start()` returns or raises within 2 s
     wall-clock each (`time.monotonic`). Level 0 is `["\\/","x"]`; level k+1 is `["\\/","<urllib.parse.quote(level k, safe='')>"]`.
     Each outcome is deterministic, and the test asserts it.
   - A JSON array of 1,025 distinct short strings refuses (candidate budget).
   - A value whose candidates exceed 1,048,576 summed characters but not 1,024 candidates refuses (character
     budget).
   - A JSON array of 1,000 copies of one string is accepted (dedupe: the copies count once).
   - Monkeypatch `_MAX_CANDIDATES` to 1 and show that a two-candidate clean value refuses.
2. Given `S,projects/teecustody-sim.invalid/subscriptions/c`, `["S"]`, `{"n":1,"b":true,"z":null}`, `%zz`,
   and `[1,2]`, `start()` succeeds (fakes as in T-08 criterion 5).
3. Given a `LauncherServer` with `max_concurrent_requests=1` and a failing `mint`, with
   `_LauncherUnixServer.shutdown_request` monkeypatched to call the original and then `time.sleep(0.1)`, three
   requests are sent one after another through a new raw-socket helper that reads until EOF. All three get
   `500 INTERNAL_ERROR`. This test fails deterministically with the T-08 ordering. Switch
   `test_mint_failure_is_500_without_detail_and_releases_its_slot` to the same helper.
4. Given a launcher whose `mint` blocks on an `Event` with one request in flight, call `stop()` from a thread.
   After 0.3 s that thread is still alive. After the event is set, `stop()` returns within 5 s, the client has
   200 and the minted text, and the socket path is gone. The behaviour already exists, so show this test
   failing by temporarily removing the join in `_BoundedServer.server_close`, and record that in the report.
5. Determinism: `test_launcher.py` passes 50 consecutive runs, and so does
   `test_issuer.py::test_connection_flood_is_capped_and_the_server_recovers`. Use a shell loop with no new
