## Interface contract
API.md §G rows 29–37 and the 2026-10-01b note (verbatim source; transcribe ids, checks, codes and `altered`
exactly). API.md §C `TokenMinter.mint(..., NamedCase(id))` and `parse_alteration("case", id)` are unchanged.
`parse_alteration` accepts any id in `NEGATIVE_CASES`, so the CLI's `--case` gains the rows with no T-16
change.

Behaviour (fixed):
- `_case_edits` returns one `DropClaim` of the row's path for each of rows 29–36:
  - `hwmodel_missing` → `("hwmodel",)`; `swname_missing` → `("swname",)`; `secboot_missing` →
    `("secboot",)`;
  - `support_attributes_missing` → `("submods","confidential_space","support_attributes")`;
  - `digest_missing` → `("submods","container","image_digest")`; `signatures_missing` →
    `("submods","container","image_signatures")`;
  - `args_missing` → `("submods","container","args")`; `env_missing` → `("submods","container","env")`.

  It returns `()` for `kid_unknown`.
- `kid_unknown`: `mint` uses `{"alg": JWS_ALG, "kid": _UNKNOWN_KID, "typ": "JWT"}`, with
  `_UNKNOWN_KID: Final = "teecustody-sim-unknown-kid"`, signs with the issuer key (`self._keys.sign_jws`) as
  usual, and leaves the payload unchanged. The header members, member order and serialisation are the default
  header's (`_json_bytes`); only the `kid` value differs.
- Unknown ids still raise `ValueError("UNKNOWN_CASE")`.
