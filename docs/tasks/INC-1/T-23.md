## Goal
The CLI never reports `INTERNAL` for an unwritable or occupied output path. It rejects `--env "=x"` at parse
time. `teecustody-sim vectors` will not overwrite existing vector files, such as the human-approved
`spec/vectors`, unless the operator passes `--force`.

## Owned files
- `packages/teecustody-sim/src/teecustody_sim/cli.py`: modify.
- `packages/teecustody-sim/tests/test_cli.py`: modify.
- `spec/vectors/README.md`: change the regeneration command to `teecustody-sim vectors --out spec/vectors/
  --force`. Nothing else.

Touching any other file is out of scope; return CONTRACT_ISSUE instead. Library start-up codes (socket path,
bind, state dir) belong to T-21. The CLI passes `SimConfigError` through unchanged, as it does now.

## Interface contract
API.md §C additions: "`vectors --out DIR [--force]`: refuses with `OUTPUT_EXISTS` (exit 2) if
`DIR/attestation/suite.cbor` or `DIR/wire/differential-corpus.json` exists, unless `--force`. Any `OSError`
while creating or writing the output is `INVALID_PATH` (exit 2)."

Behaviour (fixed):
1. `_env`: if the name before the first `=` is empty → `argparse.ArgumentTypeError(INVALID_ARGUMENT)`, so the
   output is `INVALID_ARGUMENT` and exit 2 (same as a missing `=`). The rule applies to `serve` and `up`.
2. `vectors`:
   - Add `--force` (`store_true`).
   - `_check_vectors_out` (existing type checks → `INVALID_PATH`) runs first. Then, if either output file
     `lexists` and `--force` is absent, raise `ValueError("OUTPUT_EXISTS")`. This happens before
     `generate_suite` is called, so nothing is written or created.
   - With `--force`, the existing behaviour is unchanged (regular files are replaced; symlinks and non-regular
     entries still give `INVALID_PATH`).
   - An `OSError` from `generate_suite` or `generate_corpus` → `raise SimConfigError(INVALID_PATH) from None`.
3. `up`: an `OSError` from `_launcher_dir` other than the existing `FileExistsError` path → `INVALID_PATH`.
4. `profile --out` is unchanged (it already maps `OSError` to `INVALID_PATH`). So is `_error_line`.

## Acceptance criteria (each becomes a test, in this order)
1. Given `serve … --env "=x"` and `up … --env "=x"`, exit 2, stderr exactly `INVALID_ARGUMENT\n`, and no state
   dir is created. `--env "A="` (empty value) is still accepted.
2. Given an `--out` directory that already holds `attestation/suite.cbor` (and, separately, only
   `wire/differential-corpus.json`), `vectors` exits 2 with stderr `OUTPUT_EXISTS\n`. Both existing files are
   byte-identical afterwards and no other file is created.
3. Given the same tree with `--force`, exit 0, both files are regenerated, and stdout lists both paths.
4. Given an `--out` under a directory with mode 0500, or `generate_suite` monkeypatched to raise
   `PermissionError`, exit 2 with stderr `INVALID_PATH\n` (D-01; no `INTERNAL`). If the euid is 0, the
   mode-0500 case uses the monkeypatched variant only, and the test still runs; it is not skipped.
5. Given a symlink at `--out/attestation/suite.cbor` with `--force`, `INVALID_PATH` (existing behaviour; type
   checks precede the existence check). Without `--force`, the result is also `INVALID_PATH`, not
   `OUTPUT_EXISTS`.
6. Existing `test_cli.py` vectors tests that write into a pre-populated directory now pass `--force`. No other
   assertion changes.
