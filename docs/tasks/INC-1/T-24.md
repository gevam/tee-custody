# T-24: Core `parseTrustProfile` — canonical development URLs and issuer (D-02, B-02, B-03)

Increment: INC-1   Wave: 4   Tier: STRONG   Depends on: T-10, T-15 (merged)

## Goal
A development trust profile is accepted only if its URLs and issuer are already in canonical form. The profile
then carries no host or path spelling that the injected `Fetcher` could parse differently. Production profiles
are unchanged: they are pinned to exact Google strings.

## Owned files
- `packages/teecustody-core/src/attestation/profile.ts`: modify the private `readIssuer`,
  `readDiscoveryUrl` and `readJwksOrigin` for `profile_kind` `"development"` only.
- `packages/teecustody-core/test/attestation/profile.test.ts`: modify.

Touching any other file is out of scope; return CONTRACT_ISSUE instead. If a Tech Lead contract test or a QA
acceptance test uses a non-canonical development URL and goes red, report it; do not edit it.

## Interface contract
API.md §D `parseTrustProfile` and §E are unchanged in shape. Every new rejection is
`TrustProfileError("INVALID_PROFILE")`, with the field set as the existing `fail(field)` does. `LOOPBACK_HOSTS`
is unchanged (`127.0.0.1`, `localhost`, `[::1]`).

Development rules (fixed; `url = new URL(value)`, after the existing string check):
- **issuer**: `url.protocol === "https:"`; `url.origin === value` (so no path, no trailing `/`, no default
  port, lowercase host, no userinfo); `!url.hostname.endsWith(".")`;
  `url.hostname !== "confidentialcomputing.googleapis.com"`. This replaces the current `origin === GOOGLE_ISSUER`
  test and closes B-03.
- **discovery_url**: `url.href === value` (closes D-02 and B-02; `0x7f.1`, `127.1`, `2130706433`, `:80`,
  uppercase scheme and full-width hosts all fail); `isLoopback(url)`; `url.username === ""`;
  `url.password === ""`; `url.pathname === "/.well-known/openid-configuration"`; `url.search === ""`;
  `url.hash === ""`.
- **jwks_origin**: existing rule (`isLoopback(url) && url.origin === value`), unchanged.

## Acceptance criteria (each becomes a test, in this order)
1. Each of these development `discovery_url`s is rejected with field `discovery_url`:
   - `http://0x7f.1/.well-known/openid-configuration` (the D-02 repro), `http://127.1/…`,
     `http://2130706433/…`;
   - `http://127.0.0.1:80/…`, `HTTP://127.0.0.1/…`, `http://127.0.0.1/x`;
   - `http://127.0.0.1/.well-known/openid-configuration?a=1` and `…#f`;
   - `http://u@127.0.0.1/…`, `http://[0:0:0:0:0:0:0:1]/…`, `http://LOCALHOST/…`.
   Here `…` is `.well-known/openid-configuration`.
2. Each development `issuer` is rejected with field `issuer`: `https://confidentialcomputing.googleapis.com.`,
   `https://tee-sim.localhost/`, `https://tee-sim.localhost/p`, `https://TEE-SIM.localhost`,
   `https://tee-sim.localhost:443`, `https://u@tee-sim.localhost`, `https://tee-sim.localhost.`.
3. These are accepted: `https://tee-sim.localhost` and `https://issuer.unit.test` as issuers; discovery URLs
   `http://127.0.0.1:8791/.well-known/openid-configuration`, `http://[::1]:8791/…` and `http://localhost:8791/…`;
   the vector suite's `profile_json` (`spec/vectors/attestation/suite.cbor`, via the existing test helper);
   and the existing production fixture (unchanged rules).
4. The returned profile's `discovery_url` is the input string (now provably equal to `url.href`).
