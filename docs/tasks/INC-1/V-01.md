## Goal
Before any Wave 1 code depends on them, every row of `docs/tasks/INC-1/FACTS.md` is confirmed against current
official Google Cloud documentation, with source URL and access date recorded. Mismatches reach the Tech Lead
as a CONTRACT_ISSUE before Wave 1 starts, not as review findings after it. This is a verification task
(pattern of INC-2's V-2.1); it writes no code.

## Owned files
- `docs/tasks/INC-1/FACTS.md` (modify: fill only the `Source URL`, `Accessed`, `Verdict` columns)

Touching any other file, or the `Value` column, is out of scope — return CONTRACT_ISSUE instead.

## Interface contract
Spec text you are verifying against (verbatim):
- §0: "Before implementing anything that touches Google Cloud Attestation, Confidential Space token claims,
  Cloud KMS, Workload Identity, or a cryptographic library, verify the details against the current official
  documentation and record the source and version you relied on. Claim names, endpoints and APIs change."
- §6 (closing): "The claim paths above reflect the documentation at the time of writing. The implementer MUST
  confirm them against the current Confidential Space token-claims reference and record which version was
  consulted."
- §15.2 item 1: "A local process that mounts the same Unix socket path the real launcher exposes and implements
  the same token endpoint, with the same request schema (`audience`, `nonces`, `token_type`) and the same
  constraints on nonce count and length (confirm against current launcher documentation)."

Sources: only `cloud.google.com` / `docs.cloud.google.com` Confidential Space pages (token claims reference,
custom attestation tokens / launcher, signed container images), the live discovery document at
`https://confidentialcomputing.googleapis.com/.well-known/openid-configuration`, and the
`google/go-tpm-tools` launcher source on GitHub (record the commit SHA). Blogs, answers and model memory are not sources.

## Acceptance criteria (each is checked by the Orchestrator against FACTS.md)
1. Given each row F-01 … F-15, when verified, then `Source URL` holds at least one allowed source (anchored
   to the section), `Accessed` holds the date (YYYY-MM-DD), and `Verdict` is `confirmed`, `differs: <actual
   value>` or `not documented`.
2. Given F-07, the `Verdict` cell records the current `jwks_uri` value and its origin.
3. Given F-09, the `Verdict` cell lists every currently documented `hwmodel` value.
4. Given F-12, the `Verdict` states whether the exact signed bytes are reconstructible from token claims
   alone, and quotes the documented payload format if one exists.
5. Given any `differs` or `not documented` verdict, the Task Report status is CONTRACT_ISSUE and lists the rows.
