# D-03: gateway never times out a connection that stops sending request headers (slowloris on the header phase)

Increment: INC-2   Severity: Medium   Found by: QA
Violates: SR-4 (concurrency/resource budgets on public ingress; gateway hardening "slowloris" intent, INC-2-API §6)   Affects task(s): T-14 (gateway), T-31 (harness server config)
Status: CLOSED (2026-10-15) — fixed by T-40, merged 03f8aaa (D-076)

## Reproduction
1. Start the gateway as the harness does: `uv run python tests/e2e/channel_harness.py --stop-on-stdin-eof` (own process group; read the `gateway=http://127.0.0.1:<port>` line).
2. Open a TCP connection to `<port>` and send only `GET /bundles HTTP/1.1\r\nHost: x\r\nX-A: ` (the header line is never finished). Send nothing more and keep the socket open.
3. Repeat for 300 connections (bind each to a different loopback source such as 127.1.0.N to avoid unrelated per-source effects; the per-source limits do not apply before a request is parsed).
4. Watch the sockets for 5 minutes with `recv`.
5. Also run `uv run pytest -q tests/acceptance/test_EXPLORE_gateway_http.py -k D03` (xfail until fixed).

Expected: the server closes (or answers 408 to) a connection that does not complete its headers within a bounded time, comparable to the 10 s `body_read_timeout_s` the T-14 hardening applies to bodies. Slow-request resource use is bounded (SR-4).
Actual: all 300 connections were still open after 5 minutes (35 s checked first, then 5 min); none was closed or answered. 1,500 held connections did not stop the gateway answering `GET /bundles` with 200 on this host (fd limit 1,048,576); with the usual container limit of 1,024 descriptors the same technique would exhaust the process' descriptors. Neither `per_source_max_in_flight` nor `max_concurrency` applies, because the request has not reached the ASGI app, and the body deadline starts only when the route begins reading the body.
