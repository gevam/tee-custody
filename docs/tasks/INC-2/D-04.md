# D-04: gateway answers protocol-level parse failures with uvicorn's plain-text body, not the documented `{"code":...}` body

Increment: INC-2   Severity: Low   Found by: QA
Violates: INC-2-API §6 "Every error body is exactly `{"code":"<CODE>"}`" (FR-5 documented contract)   Affects task(s): T-14
Status: open

## Reproduction
1. Start `uv run python tests/e2e/channel_harness.py --stop-on-stdin-eof` and read the gateway port.
2. Send `GET /bundles HTTP/1.1` with `Host: x` and a header `X-Big:` of 200,000 `a` characters (or 20,000 distinct small headers, or a TLS ClientHello instead of HTTP).
3. Read the response.

Expected: `400` with body `{"code":"INVALID_ARGUMENT"}`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.
Actual: `400` with body `Invalid HTTP request received.` (plain text, uvicorn/h11, produced before the ASGI app is reached). The status is correct and nothing is leaked; only the documented body shape differs. A host-written client that parses every 4xx body as JSON would see a parse error.

## Environment
Branch/commit: main d58f7a5   Data/fixture: harness defaults   Notes: loopback; no queue call happens.

## Suspected area
Server layer (uvicorn/h11) rather than `notes_gateway.app`; likely resolved by amending the contract text to say "except HTTP parse failures rejected by the server" (and checking `FetchTransport` maps a non-JSON 400 to a stable code).
