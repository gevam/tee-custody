## Interface contract

every "src" path):
| id | Bans | Paths |
|---|---|---|
| `tc-py-hpke-import-confined` | `import pyhpke…` / `from pyhpke…` | `/packages/teecustody-py/src/**`, exclude `/packages/teecustody-py/src/teecustody/channel/hpke.py` |
| `tc-ts-hpke-import-confined` | import of `@hpke/…` (static or literal dynamic) | `/packages/teecustody-{core,web}/src/**`, exclude `/packages/teecustody-web/src/crypto/webcrypto.ts` |
| `tc-py-no-hpke-seams` | keyword argument `eks=`, `psk=`, `psk_id=`, `pks=`, `sks=` in any call | `/packages/teecustody-py/src/**`, `/examples/**` |
| `tc-ts-no-hpke-seams` | object property `ekm`, `psk`, `pskId`, `senderKey`, `senderPublicKey` | `/packages/teecustody-{core,web}/src/**` |
| `tc-py-no-kdf-composition` (C2) | `hmac.new(…)`, `hmac.digest(…)`, `hmac.HMAC(…)`, `cryptography…hmac.HMAC(…)` (`hmac.compare_digest` allowed) | `/packages/teecustody-py/src/**`, `/examples/**` |
| `tc-ts-no-kdf-composition` (C2) | string literal `"HMAC"` used as an algorithm name/argument | `/packages/teecustody-{core,web}/src/**` |
| `tc-py-identity-sign-confined` | any `$X.sign(...)` call | `/packages/teecustody-py/src/**`, exclude `channel/prekeys.py`, `channel/identity.py` |
| `tc-py-pattern-fullmatch` (R-7) | `re.match`/`re.search` with a literal pattern ending in `$`; `$P.match(...)`/`$P.search(...)` where `$P = re.compile("…$")` in the same module | `/packages/**/*.py`, `/examples/**/*.py` |
| `tc-py-no-test-doubles` | `import tests…`, `from tests… import`; `class StaticShareOpener` | `/packages/**`, `/examples/**/src/**` |

## Acceptance criteria (each becomes a test, in this order)
1. Given `uvx semgrep==1.178.0 --test .semgrep/`, then every new rule has a positive fixture that fires and a
   negative fixture that does not (including: `hmac.compare_digest` passes; `PATTERN.fullmatch` on a `…$`
   pattern passes; `pyhpke` import in a test-path fixture passes).
1a. (A1) Given the `tc-no-verification-skip` fixtures, then each of `skipVerification`, `skip_verify`,
   `NO_VERIFY`, `noVerify`, `disableVerification`, `bypass_verif`, `insecure`, `NO_VERIFIED`,
   `NO_VERIFIED_BUNDLE_OK`, `ALLOW_NO_VERIFIED_BUNDLE`, `no_verified_bundle` and `noVerifiedBundle` fires
   (`ruleid:`). `"NO_VERIFIED_BUNDLE"` as a string literal, `NO_VERIFIED_BUNDLE` as a bare identifier and
   `"UNVERIFIED_BUNDLE"` do not fire (`ok:`). Put the `.ts` cases in the TS fixtures, and the
   `skip_verify`, `NO_VERIFY`, `NO_VERIFIED_BUNDLE` cases in the `.py` fixtures as well.
2. Given trunk after this task, then `uvx semgrep==1.178.0 --config .semgrep.yml --error --metrics=off` exits 0.
3. Given each new `tests/tooling/fixtures/violations/<case>` (`web-runtime-closure`, `hpke-closure`,
   `crypto-unpinned-range` for `@hpke/core` and `pyhpke`, `pyhpke-runtime-deps`), then the policy reports that
   violation id and exits non-zero; the `clean` fixture (A2: `@hpke/core` under Web, Core with no
   dependencies) still passes.
4. Given `ci.yml`, then a test in `test_dependency_policy.py` parses it (PyYAML is not available: use a
   line-based check) and asserts the `browser` job and the three command strings exist verbatim.
5. Given `.gitleaks.toml`, then the same test asserts the allow-list holds exactly the two paths.

6. (A3, SR Medium; ADR 0011 C5, SR-14) `tc-py-no-hpke-seams` gains four patterns, because `pyhpke` takes
   `psk`, `psk_id`, `sks`, `pks` and `eks` positionally:
   - `$S.create_sender_context($A, $B, $C, ...)`;
   - `$S.create_sender_context(..., **$KW, ...)`;
   - `$S.create_recipient_context($A, $B, $C, $D, ...)`;
   - `$S.create_recipient_context(..., **$KW, ...)`.

   The Tech Lead verified them with semgrep 1.178.0.
   - Fixtures `pos`: `suite.create_sender_context(pk, b"", b"psk", b"id")`, `(pk, b"info", b"psk")`,
     `(pk, **{"pks": p})`, `create_recipient_context(enc, sk, b"", b"psk")` and `(enc, sk, info, **opts)`.
   - Fixtures `neg`: `create_sender_context(pk, info)`, `(pk, info=b"x")`, `create_recipient_context(enc, sk, info)`
     and `(enc, sk, info=info)`.
   - T-08's `open_base` calls `create_recipient_context` with at most three positional arguments and no splat.
7. (A3, Low) `tc-ts-hpke-import-confined` tolerates comments between `from`/`import(`/`require(` and the
   specifier. Its `pattern-regex` (verified) becomes exactly:
   ```
   (?:\bfrom|\bimport\s*\(?|\brequire\s*\()(?:\s|/\*(?:[^*]|\*(?!/))*\*/|//[^\n]*)*["'`]@hpke/
   ``` New `pos` cases: `from /* x */ "@hpke/core"`, two block comments, `import(/* c */ "@hpke/core")`,
   a line comment followed by a newline, and `require("@hpke/core")` (CR). The `neg` case is
   `from "@teecustody/core"`.
8. (A3, Low) The `tc-no-verification-skip` exemption is closed against `$` and `\w` neighbours on both sides.
   The `pattern-regex` becomes exactly
   `(?i)(?:skip|disable|bypass)_?verif|(?-i:(?!(?<![\w$])NO_VERIFIED_BUNDLE(?![\w$])))no_?verif|insecure`
   (verified).
   - New `pos` cases: `NO_VERIFIED_BUNDLE$` and `$NO_VERIFIED_BUNDLE`.
   - Every earlier case keeps its outcome.
   - T-35 later applies the same shape to `INSECURE_TLS_ENVIRONMENT`.
9. (A3, Low; D-045) In `tools/dependency_policy.py`:
   - Any manifest (`dependencies`, `devDependencies`, `peerDependencies`, `optionalDependencies`) in any
     package that lists `@hpke/common` → `VIOLATION hpke-common-direct <manifest path>`. `@hpke/common` is
     admitted only transitively, through `@hpke/core`.
   - New constant `C6_SIGNED_VERSIONS = {"@hpke/core": "1.9.0", "@hpke/common": "1.10.1", "pyhpke": "0.6.5"}`
     (D-045; ADR 0011 C6). A lock entry of one of these packages at any other version →
