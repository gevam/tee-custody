every "src" path):
| id | Bans | Paths |
|---|---|---|
| `tc-py-hpke-import-confined` | `import pyhpke…` / `from pyhpke…` | `/packages/teecustody-py/src/**`, exclude `/packages/teecustody-py/src/teecustody/channel/hpke.py` |
| `tc-ts-hpke-import-confined` | import of `@hpke/…` (static or literal dynamic) | `/packages/teecustody-{core,web}/src/**`, exclude `/packages/teecustody-web/src/crypto/webcrypto.ts` |
| `tc-py-no-hpke-seams` | keyword argument `eks=`, `psk=`, `psk_id=`, `pks=`, `sks=` in any call | `/packages/teecustody-py/src/**`, `/examples/**` |
| `tc-ts-no-hpke-seams` | object property `ekm`, `psk`, `pskId`, `senderKey`, `senderPublicKey` | `/packages/teecustody-{core,web}/src/**` |
| `tc-py-no-kdf-composition` (C2) | `hmac.new(…)`, `hmac.digest(…)`, `hmac.HMAC(…)`, `cryptography…hmac.HMAC(…)` (`hmac.compare_digest` allowed) | `/packages/teecustody-py/src/**`, `/examples/**` |
| `tc-ts-no-kdf-composition` (C2) | string literal `"HMAC"` used as an algorithm name/argument | `/packages/teecustody-{core,web}/src/**` |

| `tc-py-pattern-fullmatch` (R-7) | `re.match`/`re.search` with a literal pattern ending in `$`; `$P.match(...)`/`$P.search(...)` where `$P = re.compile("…$")` in the same module | `/packages/**/*.py`, `/examples/**/*.py` |
| `tc-py-no-test-doubles` | `import tests…`, `from tests… import`; `class StaticShareOpener` | `/packages/**`, `/examples/**/src/**` |

## Acceptance criteria (each becomes a test, in this order)
1. Given `uvx semgrep==1.178.0 --test .semgrep/`, then every new rule has a positive fixture that fires and a
   negative fixture that does not (including: `hmac.compare_digest` passes; `PATTERN.fullmatch` on a `…$`
   pattern passes; `pyhpke` import in a test-path fixture passes).
2. Given trunk after this task, then `uvx semgrep==1.178.0 --config .semgrep.yml --error --metrics=off` exits 0.
3. Given each new `tests/tooling/fixtures/violations/<case>` (`web-runtime-closure`, `hpke-closure`,
   `crypto-unpinned-range` for `@hpke/core` and `pyhpke`, `pyhpke-runtime-deps`), then the policy reports that
   violation id and exits non-zero; the `clean` fixture still passes.
4. Given `ci.yml`, then a test in `test_dependency_policy.py` parses it (PyYAML is not available: use a
   line-based check) and asserts the `browser` job and the three command strings exist verbatim.
5. Given `.gitleaks.toml`, then the same test asserts the allow-list holds exactly the two paths.
