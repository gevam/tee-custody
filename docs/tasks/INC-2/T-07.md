## Goal
The workload has exactly one place that encodes and strictly decodes channel structures and builds the
signed/hashed byte layouts, so every later Python task (pre-keys, sessions, server, vectors) gets
canonical, range-checked bytes and documented errors only.

## Interface contract
INC-2-API §4.5 verbatim (signatures, rules) plus API-TL §2 (`OpenResultEnvelope`, `FrameResultEnvelope`,
`OpenResultBody`, `decode_bundle`/`decode_response` errors, `encode_open_result_plaintext` shape). Key text:
> Every decode goes through `teecustody.wire.decode` with the stated limits, then a strict schema check:
> exact key set, types, ranges, and `fullmatch` patterns. Schema rules beyond the CDDL types: every time
> field is an `int` in [0, `MAX_UNIX_S` = 2^53−1] (R-1); `prekeys` ids are strictly ascending (R-2); in a
> decoded `open_result`, `ok is True` iff `session_id is not None` (R-3). This module holds no keys and
> performs no AEAD.

```python
def decode_request(body: bytes, limits: BoundaryLimits) -> OpenRequestEnvelope | FrameRequestEnvelope: ...
    # len(body) > max_request_bytes → TOO_LARGE before decoding; any WireError or schema failure → INVALID.
    # The nested aad is decoded with limits.aad_decode and must re-encode to aad_bytes (canonical).
def decode_open_payload(pt: Secret, limits: DecodeLimits) -> OpenSessionPayload | EnrollPayload: ...
def prekey_signing_message(instance_id: str, prekey_id: int, pub: bytes, not_after: int,
                           image_digest: str) -> bytes: ...   # §2; ValueError("<FIELD>_RANGE") before hashing
def hpke_info(ik_pub: bytes, prekey_id: int) -> bytes: ...   # §2, 47 bytes
```
plus `encode_bundle`, `decode_bundle`, `encode_open_result_aad` (literal `seq` 0), `encode_frame_aad`,
`encode_open_result_plaintext`, `encode_frame_result_plaintext`, `encode_response_envelope`, `decode_response`,
`decode_open_result_plaintext` exactly as §4.5. Layouts (§2): preimage `ascii("prekey-v1") ‖ ascii(instance_id)
‖ u32be(id) ‖ pub ‖ u64be(not_after) ‖ ascii(image_digest)` = 156 B, message = SHA-256 of it; `info` =
`ascii("tee-chan-v1") ‖ SHA-256(ik_pub) ‖ u32be(prekey_id)`. Field names in errors: `INSTANCE_ID_RANGE`,
`PREKEY_ID_RANGE`, `PUB_RANGE`, `IK_PUB_RANGE`, `NOT_AFTER_RANGE`, `IMAGE_DIGEST_RANGE`. Every encoder applies the
same range checks as the decoder and raises `ValueError("<FIELD>_RANGE")`. `bool` is never accepted as `int`.
`decode_open_payload` copies `cs` into a new `Secret` and never holds another copy.

## Acceptance criteria (each becomes a test, in this order)
1. Given a valid open request built in the test with `teecustody.wire.encode`, then `decode_request` returns
   `OpenRequestEnvelope` whose `aad_bytes` are the exact nested bytes; same for a frame request.
2. Given `max_request_bytes + 1` bytes, then `EnvelopeError(TOO_LARGE)` and `wire.decode` is not called (spy).
3. Given each schema violation — unknown key, missing key, wrong type, `bool` for an int, `kind` other value,
   `enc` 31 B, `ct` 15 B, `client_id`/`instance_id` with uppercase, 31/33 chars or a trailing `"\n"`, `op` failing
   the pattern, `prekey_id` 2^32, `timestamp`/`published_at`/`not_after` 2^53 (R-1), a non-canonical nested aad,
   unsorted or duplicate pre-key ids (R-2) — then `EnvelopeError(INVALID)` (one parametrized case each).
4. Given `encode_bundle(b)`, then `decode_bundle(encode_bundle(b), …) == b`; an encoder input with ids not
   ascending raises `ValueError("PREKEY_ID_RANGE")`.
5. Given `decode_open_result_plaintext` with `ok: true` and nil `session_id`, or `ok: false` with a session id,
   then `EnvelopeError(INVALID)` (R-3); valid pairs decode.
6. Given `prekey_signing_message` inputs, then the output equals SHA-256 of the 156-byte preimage built
   independently in the test; each width/range violation raises its `ValueError` before any hashing (patch
   `hashlib.sha256` to fail if called).
7. Given `hpke_info`, then length 47 and bytes equal the §2 layout; `ik_pub` ≠ 32 B or `prekey_id` out of range
   raise.
8. Given `encode_open_result_aad`/`encode_frame_aad`/plaintext encoders, then outputs re-decode to the CDDL
   shapes with the literal `seq: 0` for open results; an `error` failing `ERROR_CODE_PATTERN` raises `ValueError`.
9. Given 5 000 seeded mutations (hypothesis or `random.Random(1)`) of valid requests and responses, then
   `decode_request`/`decode_response` only return or raise `EnvelopeError`, each call < 50 ms.

## Security requirements
- SR-3: criteria 2, 3, 5, 9 (strict schema, bounds before decode, fuzz). R-7: all patterns use `fullmatch`.
- SR-14: criteria 6–7 (layout widths checked before hashing).
- NFR-3: `cs` exists only inside the returned `Secret`.

## Constraints
