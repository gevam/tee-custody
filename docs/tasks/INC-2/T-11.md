# T-11: Implement audit record validation and serialisation (`audit/validate.py`)

Increment: INC-2   Wave: 1   Tier: STRONG (security.paths: `teecustody/audit/**`)   Depends on: T-04

## Goal
Every audit adapter (InMemory now, GCS in INC-3) calls one validator first, so no record with an
unallowed field, a malformed identifier or a misplaced `count` can be written, and records serialise to one
canonical JSON form.

## Interface contract
INC-2-API §4.12 verbatim (types live in `audit/ports.py`, final):
```python
def validate_audit(key: AuditKey, record: AuditRecord) -> None: ...   # AuditError(INVALID_ARGUMENT); both adapters call it first
def audit_json(record: AuditRecord) -> bytes: ...                     # sorted keys, None omitted, separators (",", ":")
```
> `validate_audit` rejects: id failing `AUDIT_ID_PATTERN.fullmatch`; any identifier failing
> `HEX32_PATTERN.fullmatch`; outcome failing `OUTCOME_PATTERN.fullmatch`; ints out of range or `bool`; interval
> fields on `EVENT`/`RELEASE`, only one of the pair, or `start >= end`; `count` on any non-`AGGREGATE` class,
> missing on `AGGREGATE`, or out of range.

Decisions: identifiers checked with `HEX32_PATTERN` are `actor_client_id`, `subject_client_id`,
`recovery_id`, `request_id`, `session_id`. Int ranges: `ts`, `interval_start`, `interval_end` in
[0, 2^53−1]; `prekey_id`, `epoch` in [0, 2^32−1]; `count` in [1, `MAX_COUNT`]. `AGGREGATE` requires both
interval fields. `key.record_class` must be an `AuditClass` member and every `str` field must be exactly `str`.
`audit_json` = `json.dumps({k: v for k, v in fields if v is not None}, sort_keys=True, separators=(",", ":"),
ensure_ascii=True).encode("ascii")` over the dataclass fields; the key's class and id are not in the body.

## Acceptance criteria (each becomes a test, in this order)
1. Given one valid record per class (EVENT, ALERT with/without interval, AGGREGATE with count, RELEASE), then
   `validate_audit` returns `None`.
2. Given each rejection rule above (one parametrized case per rule, including `"<32hex>\n"` for every
   identifier and `"<id>\n"` for the key id, `True` for an int, `count=0`, `count=MAX_COUNT+1`, `count` on ALERT,
   AGGREGATE without `count`, `interval_start` only, `start == end`, interval on EVENT), then
   `AuditError(INVALID_ARGUMENT)` with `str(err) == "INVALID_ARGUMENT"`.
3. Given a record, then `audit_json` is byte-identical to the documented `json.dumps` form, omits `None`
   fields and is stable across runs.
4. Given a record whose outcome or id contains a sentinel secret pattern not matching the patterns, then the
   rejection error text does not contain it (SR-11).
