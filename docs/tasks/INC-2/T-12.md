# T-12: Implement the audit emitter: aggregates, capped pre-principal alerts, retries (`audit/emitter.py`)

## Goal
Anonymous (pre-principal) channel failures become bounded per-interval `AGGREGATE` records with exact
counts, alerts are written individually and never suppressed, and an audit backend outage never breaks the
channel or grows memory without bound.

## Interface contract
INC-2-API §4.12 (emitter part) and §10 verbatim:
```python
class AuditEmitter:
    def __init__(self, sink: AuditSink, *, interval_s: int, alert_cap: int, clock: Callable[[], float],
                 rng: Callable[[int], bytes], logger: AllowListedLogger) -> None: ...
    def count(self, outcome: AggregateOutcome) -> None: ...              # O(1), in memory; saturates at MAX_COUNT
    def pre_principal_alert(self, outcome: str, *, subject_client_id: str, request_id: str | None = None,
                            epoch: int | None = None, recovery_id: str | None = None) -> None: ...
        # first per (outcome, subject_client_id) per interval → ALERT; repeats fold into AGGREGATE `outcome`;
        # beyond alert_cap ALERT objects this interval → one ALERT_CAP_REACHED (exempt from the cap), then fold.
    def alert(self, outcome: str, *, request_id: str | None = None,
              interval: tuple[int, int] | None = None) -> None: ...      # never capped or deduplicated
    def tick(self) -> None: ...       # when the interval has ended: write one AGGREGATE per outcome with count >= 1; retry pending
    def close(self) -> None: ...      # at shutdown: flush the partial interval (interval_end = now)
```
> Object ids: `AGGREGATE` `<interval_start_ms>/<outcome>/<hex(rng(8))>`; `ALERT` `<hex(rng(16))>/<outcome>`.
> `ALREADY_EXISTS` on any write → `alert("AUDIT_WRITE_CONFLICT", request_id=…)` with a fresh id. `UNAVAILABLE` →
> the record stays pending and is retried on each `tick`, at most `2 × len(AggregateOutcome)` pending records;
> beyond that the oldest is dropped and `AUDIT_PENDING_DROPPED` is logged. The emitter never raises into the channel.

Decisions (TL): interval clock in Unix ms = `int(clock() * 1000)`; the first interval starts at construction;
intervals are contiguous (`start_{k+1} = start_k + interval_s·1000`); an ended interval's AGGREGATEs carry that
interval's `interval_start`/`interval_end`; `ts` = write time in ms. Only `pre_principal_alert` ALERTs count
toward `alert_cap`; dedup set and cap counter reset per interval. `AUDIT_WRITE_CONFLICT` carries the
conflicting record's `request_id` (or none) and is not retried on conflict again. Any exception from the
sink other than `AuditError(UNAVAILABLE)` (including `INVALID_ARGUMENT`) is logged as `AUDIT_WRITE_FAILED`
and the record dropped. Validation of identifiers is the sink's job (T-11 via adapters).

## Acceptance criteria (each becomes a test, in this order; fake sink + fake clock + fixed rng)
1. Given N calls of `count(X)` for each `AggregateOutcome` within one interval, when `tick` runs after it ends,
   then exactly one AGGREGATE per outcome with `count == N`, correct interval fields and id format;
   outcomes with zero calls write nothing.
2. Given `count` called `MAX_COUNT + 5` times (simulate via a private counter seed), then `count == MAX_COUNT`.
3. Given `pre_principal_alert("KCV_MISMATCH", subject=a)` twice and for subject b once, then two ALERTs (a, b)
   and the repeat folds into AGGREGATE `KCV_MISMATCH` count 1 at interval end.
4. Given `alert_cap = 2` and 5 distinct subjects, then 2 ALERTs, one `ALERT_CAP_REACHED`, and 3 folded counts;
   the next interval starts a fresh cap.
5. Given 200 `alert("PREKEY_BURN_HIGH", interval=(s, e))` calls, then 200 ALERT records with the interval and
   no `count` (never capped or deduplicated).
6. Given the sink returns `ALREADY_EXISTS`, then an `AUDIT_WRITE_CONFLICT` ALERT is written with a new id.
7. Given the sink raises `UNAVAILABLE` for 30 writes, then at most `2 × 12` records stay pending, the oldest are
   dropped with `AUDIT_PENDING_DROPPED` logged, and pending records are written on the next successful `tick`.
8. Given `close()` mid-interval, then the partial interval is flushed with `interval_end` = now.
9. Given a sink raising any exception, then no emitter method raises; logs contain only allow-listed fields.

## Security requirements
- SR-6 / SR-12 (INC-2-API §14): criteria 1, 4, 5, 6 — aggregates with exact counts; `PREKEY_BURN_HIGH` and
  `AUDIT_WRITE_CONFLICT` never capped; flood produces `ALERT_CAP_REACHED`.
- SR-11: criterion 9 (no record content or exception text in logs).

## Constraints
