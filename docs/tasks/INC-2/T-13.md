# T-13: Read the workload's own image digest from its token (`attest/claims.py`)

## Goal
The workload binds every pre-key signature to the image it actually runs, read from the launcher-issued
token, and refuses to start on a token whose digest claim is missing or malformed.

- `packages/teecustody-py/src/teecustody/attest/claims.py` (stub from T-04; `IMAGE_DIGEST_PATTERN` frozen)

Touching any other file is out of scope — return CONTRACT_ISSUE instead.

## Interface contract
INC-2-API §4.3 verbatim:
```python
IMAGE_DIGEST_PATTERN: Final = re.compile(r"sha256:[0-9a-f]{64}")   # IMAGE_DIGEST_PATTERN.fullmatch only (R-7)
def own_image_digest(token: AttestationToken, *, max_token_bytes: int) -> str: ...
    # Reads submods.container.image_digest from the launcher-supplied token (trusted source, spec §11).
    # LauncherError(TOKEN_REJECTED) if the token exceeds max_token_bytes, is not three base64url segments,
    # the payload is not a JSON object, or the claim is absent or does not match IMAGE_DIGEST_PATTERN.
```
Decisions: size is `len(token.value.encode("ascii"))` (non-ASCII → `TOKEN_REJECTED`); segments split on `.`
must be exactly 3, each non-empty and strict base64url without padding (reuse the rule of INC-1
`attest/token.py`: alphabet `[A-Za-z0-9_-]`, canonical length); payload decoded as UTF-8 JSON;
`submods` and `container` must be JSON objects and `image_digest` a `str`. No signature verification
(the token comes from the local launcher). Errors raised `from None`.

## Acceptance criteria (each becomes a test, in this order)
1. Given a simulator-shaped token (built in the test) with `submods.container.image_digest = "sha256:" + 64
   hex`, then that string is returned.
2. Given a token one byte over `max_token_bytes`, then `TOKEN_REJECTED` before any decoding (spy on
   `json.loads`).
3. Given 2 or 4 segments, an empty segment, `=` padding, a non-base64url character, a non-UTF-8 or non-JSON
   payload, a JSON array payload, `submods` missing or not an object, `container` missing, `image_digest`
   missing, uppercase hex, 63 hex, `sha512:` prefix, and the valid digest + `"\n"` (R-7), then
   `LauncherError(TOKEN_REJECTED)` (one parametrized case each) with `__cause__` and `__context__` `None`.
4. Given a token from the running simulator (`teecustody_sim.Simulator`, as INC-1's launcher contract test
   does) obtained via `ConfidentialSpaceLauncher`, then the returned digest equals the simulator
   `LaunchConfig.image_digest`.

## Security requirements
