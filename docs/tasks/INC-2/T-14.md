## Goal
Browsers reach the workload only through an untrusted, rate-limited relay that validates every path and
size before touching the queue, never reads or logs a body, and leaks no route existence.

## Interface contract
INC-2-API §6 verbatim (route table, the five bullet rules, `QueueError` mapping) and API-TL TL-4. Signature:
```python
def create_app(queue: RelayQueue, *, limits: GatewayLimits = GatewayLimits(),
               rng: Callable[[int], bytes] = os.urandom,
               clock: Callable[[], float] = time.monotonic) -> fastapi.FastAPI: ...
```
Fixed decisions:
- Routes: `GET /bundles` → `queue.list_bundles(limits.max_bundles)`; `POST /requests/{instance}` →
  `queue.publish_request(instance, rng(16).hex(), body)`; `GET /responses/{client}` →
  `queue.pull_responses(client, after, limits.max_page)`. JSON bodies are produced with `json.dumps(...,
  separators=(",", ":"))`, `Content-Type: application/json`.
- The body is read as a stream and rejected with 400 the moment it exceeds `max_request_bytes` or differs from
  `Content-Length`; `Content-Type` must equal `application/octet-stream` exactly (parameters rejected).
- Token buckets: refill `rate` tokens/s from `clock`, capacity `burst`, one token per request; global bucket
  checked before the per-source bucket; per-source buckets in an LRU of `max_sources_tracked` keyed by
  the **source key** of INC-2-API §6 "Gateway hardening" (A1). IPv4 keys on the address, IPv4-mapped IPv6 on its
  IPv4 address, other IPv6 on its /64 network, and a missing or unparseable peer on `"unknown"`. The check
  order, the per-source in-flight cap, the `finally` release and the in-flight table bound are all as §6 states. Concurrency: a counter around the handler; excess →
  429. `Retry-After` = `ceil(seconds until one token)`, minimum 1; concurrency 429 uses `Retry-After: 1`.
- Validation errors from FastAPI/Starlette (including 404/405 for unknown routes and methods) are replaced by the
  §6 bodies via exception handlers; every response, including errors and CORS preflight, carries
  `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. OpenAPI/docs routes are disabled
  (`docs_url=None, redoc_url=None, openapi_url=None`).
- Logging: `teecustody.obs.get_logger("gateway")`, one `info` line per request with outcome
  `GATEWAY_<CODE>` (e.g. `GATEWAY_OK`, `GATEWAY_RATE_LIMITED`) and no fields (paths, ids and bodies are not
  logged; HTTP status is implied by the code).

## Acceptance criteria (each becomes a test, in this order; `fastapi.testclient.TestClient` + a recording fake `RelayQueue`)
1. Given two live bundles, then `GET /bundles` → 200 with exactly `{"bundles":[{"instance_id","bundle"}]}`,
   unpadded base64url, at most `max_bundles`.
2. Given a valid POST, then 202 `{"request_id":"<32hex>"}` equal to `rng(16).hex()` and the queue saw the raw
   bytes unchanged.
3. Given `instance`/`client` with uppercase hex or 31 or 33 chars, and an `after` query value failing
   `CURSOR_PATTERN` (incl. a trailing `%0A` in the query), then 400 `{"code":"INVALID_ARGUMENT"}` and zero queue
   calls. A `%0A` in the path is a 404 (A1, criterion 16).
4. Given an empty body, a body of `max_request_bytes + 1`, a missing `Content-Length`, a wrong or parameterised
   `Content-Type`, then 400 and zero queue calls.
5. Given `QueueError` codes `INVALID_ARGUMENT`, `NOT_FOUND`, `UNAVAILABLE`, `CONFLICT`, `INTERNAL` and a raw
   `RuntimeError("SENTINEL")`, then 400 / 404 `UNKNOWN_INSTANCE` / 503 / 500 / 500 / 500, bodies exactly
   `{"code":…}` and `SENTINEL` absent from body and logs.
6. Given an unknown client route, then 200 with `{"responses":[],"next":null}` (D2-13).
7. Given per-source, global and concurrency limits exceeded (fake clock), then 429 `RATE_LIMITED` with
   `Retry-After` before any queue call; an in-budget second source still succeeds; refill restores service.
8. Given `max_sources_tracked = 2` and three sources, then the least recently used bucket is evicted.
9. Given default limits, then no `Access-Control-*` header on any response; with
   `cors_origins=("https://app.example",)` only an exact matching `Origin` gets `Access-Control-Allow-Origin`
   and `Vary: Origin`, preflight allows only `GET, POST` and `Content-Type`, and
   `Access-Control-Allow-Credentials` never appears.
10. Given `cors_origins` entries `"*"`, `"http://example.com"`, `"https://a.example/path"`,
    `"https://a.example "`, then `ValueError("INVALID_CORS_ORIGIN")` at `create_app`;
    `"http://127.0.0.1:5173"` and `"http://localhost:8080"` are accepted. Invalid numeric limits →
    `ValueError("INVALID_LIMITS")`.
11. Given unknown path / method, then 404 `NOT_FOUND` / 405 `METHOD_NOT_ALLOWED` with the security headers.

12. (A1, §6 order) Given limits that trip each check in turn, then the response comes from the first failing
    check in the §6 order (per-source in-flight, global concurrency, global bucket, per-source bucket,
    control-character path, routing), and no queue call is made.
13. (A1, body deadline) Given §6's reproduction (64 POSTs from one source, each declaring 65536 bytes and sending
    1 byte; injected short `body_read_timeout_s`), then at most `per_source_max_in_flight` are in flight and the
    rest get 429. A second source is served at once. Every held request then gets
    `408 {"code":"REQUEST_TIMEOUT"}` with `Connection: close`, nothing is published, and the in-flight table is
    empty.
14. (A1, CR Medium) Given `max_concurrency=1`, when a request is cancelled or the client disconnects mid-body,
    then the next request is served: both slots were released in `finally`.
15. (A1, source key) Given peers `2001:db8::1` and `2001:db8::2`, then they share one per-source bucket, while
    `2001:db8:0:1::1` gets its own. `::ffff:192.0.2.1` and `192.0.2.1` share a key. A loopback peer sending
    `X-Forwarded-For: 203.0.113.9` is keyed on the peer address.
16. (A1, CR Medium, R-7) Given `/bundles%0A`, `/bundles%00`, `/requests/<32hex>%0A`, `/responses/<32hex>%0D` and a
    raw `%7F`, then each gets `404 {"code":"NOT_FOUND"}` with zero queue calls.
17. (A1, CR Low) Given every pattern this task defines or reuses, then the pin test compares both `.pattern` and
    `.flags` with the spec.
18. (A1, TL-4 extended) Given `per_source_max_in_flight` of 0, `max_concurrency + 1` or `True`, or
    `body_read_timeout_s` of 0.5, 60.5, `inf` or `nan`, then `create_app` raises `ValueError("INVALID_LIMITS")`.
    The README states the deployment requirement: run uvicorn with `proxy_headers=False`,
    `server_header=False` and `access_log=False`, never set `forwarded_allow_ips`, and behind a proxy the
    per-source limit collapses to the global limit. A test reads the README and asserts the three settings
    are named.
