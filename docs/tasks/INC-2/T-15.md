# T-15: Implement the Core channel wire codec (`channel/wire.ts`)

Increment: INC-2   Wave: 1   Tier: STRONG (security.paths: Core `src/channel/**`)   Depends on: T-02, T-03 (text only)

## Goal
Core has one module that builds the canonical open/frame request bytes and strictly decodes responses, with
the same schema rules and range checks as the Python codec, so the client never trusts an unchecked field.

## Interface contract
INC-2-API §7.3 and the API-TL §3 `channel/wire.ts` block (copy exactly; every function and type listed
there). Normative text:
> All of them go through `encodeCanonical`/`decodeCanonical` only, with exact-key-set schema checks. Patterns
> are `^…$` with no flags. Time fields and `seq` must be safe-integer `number`s ≤ 2^53−1. A `bigint` fails the
> schema (R-1). `decodeOpenResultPlaintext(pt, aad)` enforces `ok === true` ⇔ `aad.session_id !== null` (R-3).
> The nonce builder is **not** exported from `channel/wire.ts`.

Shapes are spec/wire `channel.cddl` (T-03): open-request `{kind,aad,enc(32),ct(16..2048)}`, frame-request
`{kind,aad,ct(16..32784)}`, responses `{kind,aad,ct(16..32784)}`, `open-result-aad {session_id: bstr16 | nil,
request_id: bstr16, seq: 0}`, `frame-aad {session_id: bstr16, seq, op}`, `open-result`, `frame-result`,
`open-plaintext`. `decodeResponse` decodes the envelope with `envelopeDecode`, then the nested `aad` with
`aadDecode`, re-encodes the nested aad and requires byte equality. Builder `RangeError` codes:
`CLIENT_ID_RANGE`, `INSTANCE_ID_RANGE`, `PREKEY_ID_RANGE`, `REQUEST_ID_RANGE`, `TIMESTAMP_RANGE`,
`SESSION_ID_RANGE`, `SEQ_RANGE`, `OP_RANGE`, `ENC_RANGE`, `CT_RANGE`, `IK_PUB_RANGE`, `CS_RANGE`,
`KEY_ID_RANGE`, `EPOCH_RANGE` — every check runs before encoding or hashing. Error-string values in result
plaintexts are kept as received (mapping to `RemoteErrorCode` is T-26's job) but must match
`ERROR_CODE_PATTERN`.

## Acceptance criteria (each becomes a test, in this order)
1. Given valid inputs, then `encodeOpenAad`, `encodeOpenRequest`, `encodeFrameAad`, `encodeFrameRequest`,
   `encodeOpenPlaintext` produce bytes that `decodeCanonical` maps to exactly the CDDL key sets and values
   (expected bytes written as hex literals in the test for one case each).
2. Given each builder input out of range (one case per `RangeError` code above; include `timestamp = 2**53`,
   `seq = -1`, `seq = 2**53`, `prekeyId = 2**32`, `clientId` uppercase or 31 chars, non-integer numbers),
   then the named `RangeError` and `sha256`/encoder spies are not called.
3. Given encoded `open_result` and `frame_result` envelopes (built with `encodeCanonical` in the test), then
   `decodeResponse` returns the typed envelope with `aadBytes` equal to the nested bytes.
4. Given unknown/missing keys, wrong `kind`, a nested aad that is not canonical, `ct` 15 bytes, `seq` encoded
   as 2^53 (decodes to `bigint`, R-1), and `open-result-aad.seq` ≠ 0, then `decodeResponse` throws
   `WireError` (schema failures: `WireError("MALFORMED")`).
5. Given `decodeOpenResultPlaintext` with `ok: true` + `sessionId: null`, or `ok: false` + a session id (R-3),
   an `error` failing the pattern, or extra keys, then `ChannelError("INVALID_RESPONSE")`; the valid pairs decode.
6. Given `decodeFrameResultPlaintext` with `re` as `bigint`, missing `re`, or extra keys, then
   `ChannelError("INVALID_RESPONSE")`.
7. Given `hpkeInfo`, then 47 bytes equal to `ascii("tee-chan-v1") ‖ SHA-256(ikPub) ‖ u32be(prekeyId)`;
   `ikPub` of 31 bytes → `RangeError("IK_PUB_RANGE")`.
8. Given the module's exports, then no export name contains `nonce` and no exported function has a parameter
   named `seq` (inspect `Function.prototype.toString` of each export for the parameter list).
9. Given 5 000 seeded mutations of valid responses, then `decodeResponse` only returns or throws `WireError`,
   each call < 50 ms.
