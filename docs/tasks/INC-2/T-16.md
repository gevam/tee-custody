## Goal
The client only ever seals to a pre-key whose bundle passed every spec §5.2 binding check — attestation,
identity nonce, every pre-key signature over the attested image digest — and whose key is comfortably
unexpired; anything else fails closed with a typed error.

## Interface contract
INC-2-API §7.2 verbatim (types in `bundle/types.ts` are final; `createVerifiedBundle` is API-TL §3):
```ts
export function verifyBundle(published: PublishedBundle, profile: TrustProfile,
    events: SecurityEventSink, deps: BundleDeps): Promise<VerifiedBundle>;
export function prekeySigningMessage(crypto: Pick<Crypto, "sha256">, instanceId: string, id: number,
    pub: Bytes, notAfter: number, imageDigest: string): Promise<Bytes>; // §2
export function selectPreKey(bundle: VerifiedBundle, used: ReadonlySet<number>, nowMs: number,
    crypto: Pick<Crypto, "randomBytes">): VerifiedPreKey | undefined;
// uniform random among prekeys with id ∉ used and notAfterMs > nowMs + 5000; undefined if none.
```
Verification order (normative, §7.2): (1) `decodeCanonical(bundle, limits.decode)` + strict schema —
every time field a safe-integer `number` in [0, 2^53−1] (`bigint` → `MALFORMED`), ids strictly ascending, ≤
`maxPrekeys` entries — else `MALFORMED`; (2) `instance_id !== published.instanceId` → `INSTANCE_MISMATCH`;
(3) `verifyAttestation(token, profile, { identityNonce: sha256(IK_pub) }, events, …)`, any `AttestationError`
→ `ATTESTATION_FAILED` with its `check`; (4) brand check `isVerifiedAttestation` (B-13) else
`ATTESTATION_FAILED`; (5) for **every** entry, expired or not, `verifyEd25519(IK_pub, m, sig)` with `m` built
from `va.imageDigest`; `false` → `PREKEY_SIGNATURE_INVALID`, `CapabilityError("UNSUPPORTED")` →
`UNSUPPORTED`, any other rejection → `PREKEY_SIGNATURE_INVALID`; (6) only then keep entries with
`not_after × 1000 > now()`; none → `NO_USABLE_PREKEY`. Builder inputs are range-checked first (`RangeError` →
`MALFORMED`). The result is built with `createVerifiedBundle` (`verifiedAtMs = now()`, prekeys sorted by id,
`notAfterMs = not_after × 1000`). Uniform selection: rejection sampling over `randomBytes(4)` (no modulo bias).

## Acceptance criteria (each becomes a test, in this order; bundles built by `support.ts` with WebCrypto
Ed25519 and tokens from `test/support/jws.ts`)
1. Given a valid bundle, then a branded `VerifiedBundle` with all unexpired ids; `isVerifiedBundle` true.
2. Given each schema failure (unknown key, `IK_pub` 31 B, `sig` 63 B, 257 entries, ids `[2,1]` and `[1,1]`,
   `published_at`/`not_after` = 2^53, non-canonical bytes, > `maxBytes`), then `BundleError("MALFORMED")` and
   `fetcher.get` never called.
3. Given a published instance id different from the bundle's, then `INSTANCE_MISMATCH` before any fetch.
4. Given a token whose nonce ≠ SHA-256(IK_pub), or a debug-mode token, then `ATTESTATION_FAILED` with
   `attestationCheck` `"nonce"` / `"platform"`, and the debug case reports `ATTESTATION_DEBUG_MODE` once.
5. Given `verifyAttestation` stubbed (vitest module mock) to return an unbranded structural copy, then
   `ATTESTATION_FAILED` (B-13).
6. Given one corrupted signature on a valid entry, one on an **expired** entry, or a signature over a
   different image digest or instance id, then `PREKEY_SIGNATURE_INVALID` (Q3: signatures before filtering).
7. Given `verifyEd25519` throwing `CapabilityError("UNSUPPORTED")`, then `BundleError("UNSUPPORTED")`.
8. Given all entries expired, then `NO_USABLE_PREKEY`; given some expired, only unexpired ids returned.
9. Given `prekeySigningMessage` inputs, then SHA-256 of the 156-byte preimage; each width/range violation →
   `RangeError` before `sha256` is called.
10. Given `selectPreKey` with `used` covering some ids and one key at `notAfterMs = nowMs + 5000`, then that key
    and used keys are never returned (10 000 draws) and every other key is drawn (χ² p > 0.001).
11. Given 2 000 seeded mutations of a valid bundle, then only `BundleError` is thrown, each < 200 ms.
