# T-18: Implement `FetchFetcher` with the B-06 boundary controls (`fetch/fetcher.ts`)

Increment: INC-2   Wave: 1   Tier: STRONG (security.paths: Web `src/fetch/**`)   Depends on: T-02

## Goal
Discovery and JWKS documents are fetched only from canonical, credential-free, redirect-free URLs with a
streaming size bound, so a hostile network path cannot redirect, inflate or smuggle attestation inputs.

## Interface contract
INC-2-API §8.2 verbatim:
```ts
export type FetchFn = (input: string, init: RequestInit) => Promise<Response>;
export interface FetchFetcherOptions {
    readonly maxBodyBytes: number;        // positive safe integer; >= VerifierLimits.maxDiscoveryBytes and maxJwksBytes
    readonly timeoutMs: number;           // positive safe integer
    readonly fetch?: FetchFn;             // default globalThis.fetch
}
export class FetchFetcher implements Fetcher {
    constructor(options: FetchFetcherOptions);   // TypeError("INVALID_CONFIG") on bad options
    get(url: string): Promise<FetchResponse>;
}
```
`get`, in order:
1. `new URL(url)` fails, `parsed.href !== url` (B-06 canonical form), userinfo or fragment present, scheme not
   `https:` — except `http:` with hostname `127.0.0.1`, `[::1]` or `localhost` → `INVALID_ARGUMENT`.
2. `fetch(url, { method: "GET", redirect: "manual", credentials: "omit", cache: "no-store",
   referrerPolicy: "no-referrer", signal })`; network failure or `timeoutMs` abort → `UNAVAILABLE`.
3. `response.type === "opaqueredirect"`, `response.redirected`, a 3xx status, or a non-empty `response.url` ≠ `url`
   → `HTTP_ERROR` (no redirect is followed, D2-14).
4. Status outside 200–299 → `HTTP_ERROR` (body cancelled).
5. `Content-Length` > `maxBodyBytes` → `INVALID_RESPONSE` before reading. Read `response.body` as a stream and
   cancel as soon as the running total exceeds `maxBodyBytes` → `INVALID_RESPONSE`.
6. Resolve `{ status, body }`.

Decisions: the constructor checks only that both numbers are positive safe integers (the `>=` relation to
`VerifierLimits` is the caller's configuration; document it in the TSDoc). Timeout uses `AbortController`
and `setTimeout`, cleared in `finally`; the abort also covers body streaming. A malformed `Content-Length`
(not a non-negative decimal integer) → `INVALID_RESPONSE`. A `null` body resolves an empty `Uint8Array`.
Every rejection is `CapabilityError(code)` with no cause and no URL or body text.

## Acceptance criteria (each becomes a test, in this order; injected `fetch` spy returning `new Response(...)`)
1. Given a canonical https URL and a 200 body, then `{status: 200, body}` and the spy saw exactly the §8.2 init
   (`credentials: "omit"`, `redirect: "manual"`, `cache: "no-store"`, `referrerPolicy: "no-referrer"`).
2. Given `https://Example.com/x` (non-canonical), `https://u:p@a.example/`, `https://a.example/#f`,
   `http://a.example/`, `ftp://a.example/`, and `not a url`, then `INVALID_ARGUMENT` and the spy was never called;
   `http://127.0.0.1:8080/x`, `http://[::1]:1/x`, `http://localhost:1/x` are fetched.
3. Given a same-origin 302, a cross-origin 302, `type: "opaqueredirect"`, `redirected: true`, and `url` ≠ input,
   then `HTTP_ERROR`.
4. Given 404 and 500, then `HTTP_ERROR` and the body stream was cancelled.
5. Given `Content-Length: maxBodyBytes + 1`, then `INVALID_RESPONSE` before any read; given a chunked stream that
   crosses the limit in its third chunk, then `INVALID_RESPONSE` and the stream's `cancel` was called (no
   fourth chunk pulled).
6. Given a fetch that never resolves, then `UNAVAILABLE` after `timeoutMs` (fake timers); a rejecting fetch →
   `UNAVAILABLE`.
7. Given constructor options `0`, `-1`, `1.5`, `NaN`, `2**53`, then `TypeError("INVALID_CONFIG")`.
8. Given any rejection, then the error message equals its code and contains no URL or body text.
