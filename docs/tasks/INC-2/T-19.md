# T-19: Implement `FetchTransport` against the gateway contract (`transport/fetch-transport.ts`)

Increment: INC-2   Wave: 1   Tier: STRONG (security.paths: Web `src/transport/**`)   Depends on: T-02

## Goal
The browser talks to the untrusted gateway through a transport that validates its own arguments, sends no
credentials, follows no redirects, bounds every response and accepts only gateway JSON of the exact §6 shape.

## Interface contract
INC-2-API §8.3 verbatim, against the §6 route table:
```ts
export interface FetchTransportOptions {
    readonly baseUrl: string;             // https origin (+ optional path prefix); http only on loopback hosts
    readonly maxResponseBytes: number;    // default 1048576
    readonly timeoutMs: number;
    readonly fetch?: FetchFn;
}
export class FetchTransport implements Transport {
    constructor(options: FetchTransportOptions);   // TypeError("INVALID_CONFIG")
    listBundles(): Promise<readonly PublishedBundle[]>;
    postRequest(instance: InstanceId, body: CanonicalEnvelope): Promise<RequestId>;
    getResponses(client: ClientId, after?: ResponseCursor): Promise<ResponsePage>;
}
```
> Same fetch options as §8.2 (`redirect: "manual"`, `credentials: "omit"`, no-store); `postRequest` sends
> `Content-Type: application/octet-stream`. Arguments not matching the §6 patterns → `INVALID_ARGUMENT` before any
> request. Status mapping: 200/202 with a body that is strict JSON of exactly the §6 shape (unknown keys rejected;
> base64url strict via `base64UrlDecode`; ids/cursor re-validated) → success, else `INVALID_RESPONSE`;
> 400 → `INVALID_ARGUMENT`; 404 → `NOT_FOUND`; 429, 503 → `UNAVAILABLE`; redirect or oversize body →
> `INVALID_RESPONSE`; network/timeout → `UNAVAILABLE`; anything else → `INTERNAL`. `next: null` → `undefined`.

Decisions: `maxResponseBytes` and `timeoutMs` are required (the "default 1048576" comment is the value hosts
should pass); each must be a positive safe integer. `base64UrlDecode` is Core's (`@teecustody/core`), and the
decoded bytes must re-encode to the same text (canonical). `baseUrl` must be canonical (`new URL(baseUrl).href === baseUrl`),
end with `/`, have no query, fragment or userinfo; URLs are `new URL("bundles", baseUrl)`,
`new URL("requests/" + instance, baseUrl)`, `new URL("responses/" + client + (after ? "?after=" + after : ""), baseUrl)`.
Body size is enforced while streaming as in T-18. Strict JSON: parse with a duplicate-key-rejecting parser
written in this file (reject duplicate member names at any depth) — `JSON.parse` alone is insufficient.
`body` sent as an `ArrayBuffer` copy. `listBundles` requires 200; `postRequest` 202; `getResponses` 200.
Patterns: instance/client/request ids `^[0-9a-f]{32}$`, cursor `^[A-Za-z0-9_-]{1,128}$`.
`body` length 1..65536 else `INVALID_ARGUMENT`.

## Acceptance criteria (each becomes a test, in this order; injected `fetch` spy)
1. Given gateway-shaped 200/202 responses, then each method returns the typed values; `next: null` →
   `undefined`; the spy saw `credentials: "omit"`, `redirect: "manual"`, `cache: "no-store"` on every call and
   `Content-Type: application/octet-stream` on POST.
2. Given an instance/client of 31 chars, uppercase, or `"<32hex>\n"`, a cursor with `/` or 129 chars, or a 0- or
   65 537-byte body, then `INVALID_ARGUMENT` and the spy was never called.
3. Given response JSON with an unknown key, a duplicate key (`{"bundles":[],"bundles":[]}`), padded or
   non-canonical base64url, an `instance_id`/`request_id` outside its pattern, a `next` cursor outside its
   pattern, wrong types, or invalid JSON, then `INVALID_RESPONSE`.
4. Given statuses 400, 404, 429, 503, 500, 418 and a 302, then `INVALID_ARGUMENT`, `NOT_FOUND`, `UNAVAILABLE`,
   `UNAVAILABLE`, `INTERNAL`, `INTERNAL`, `INVALID_RESPONSE`.
5. Given a streamed body crossing `maxResponseBytes`, then `INVALID_RESPONSE` and the stream was cancelled.
6. Given a network error and a timeout, then `UNAVAILABLE`.
7. Given `baseUrl` values `http://a.example/`, `https://a.example` (no slash), `https://a.example/?q=1`,
   `https://u@a.example/`, then `TypeError("INVALID_CONFIG")`; `http://127.0.0.1:8080/` is accepted.
8. Given any failure, then the error message equals its code and contains no body or URL text.

## Security requirements
- SR-3 / R-7: criteria 2–3 (INC-2-API §14 "FetchTransport rejects gateway JSON with unknown or duplicate keys,
  non-canonical base64url, or an id/cursor outside its pattern"). SR-1/SR-5: criterion 1 (`credentials: "omit"`
  asserted on every request), criterion 4 (no redirect followed). SR-11: criterion 8.
