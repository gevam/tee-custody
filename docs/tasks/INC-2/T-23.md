## Goal
No AES-GCM nonce is ever reused under a session key: the workload's only t2c sealing path allocates and
persists `seq` before encrypting, c2t frames are accepted strictly in increasing order, and a full session
table evicts one idle session before refusing service.

## Interface contract
INC-2-API §4.9 (`SessionRejectCode` … `SessionTable`, "Nonce discipline", "Idle and eviction") verbatim, and
API-TL §2 (`open_frame`, `_nonce`). Core lines:
> `T2cSealer`: Sole owner of `sk_t2c` and the t2c counter. `seal_open_result` … Allowed only while
> `next_seq == 0`, else `SessionReject(USED)`. Sets `next_seq = 1` BEFORE encrypting, so an exception can never
> leave nonce 0 reusable. `seal_frame_result` … `seq = next_seq; next_seq = seq + 1` (persisted first); then build
> frame-aad `{session_id, seq, op}` and encrypt. `seq == 0` (open_result not yet sealed) → `USED`; `seq > MAX_SEQ`
> → `EXHAUSTED`. There is no getter, setter, reset or decrement for `next_seq`, and no method takes a seq, a nonce
> or a key.
> `Session.open_c2t`: seq <= last accepted → `SEQ_REJECTED` (before decrypt); AEAD failure → `AUTH_FAILED`; state
> unchanged on failure. On success: `last_c2t_seq = seq`, `last_activity = now`.
> `SessionTable.create`: `t2c` must be fresh, else `ValueError("T2C_USED")` … (1) existing session for this
> principal closed first (`REPLACED`); (2) if still full: `expire_idle()`; then evict (R-8); else
> `OverflowError("SESSIONS_FULL")`. Takes ownership of `sk_c2t` and `t2c`.

Decisions: AES-256-GCM from `cryptography` (`AESGCM`), key revealed only inside the call; `seal_open_result`
returns `(encode_open_result_aad(...), ct)`; `seal_frame_result` returns `(encode_frame_aad(...), ct)` and
`Session.seal_t2c` returns `(FrameAad, aad_bytes, ct)`. `open_c2t` checks `aad.session_id == self.session_id`
(else `AUTH_FAILED`). `close`/eviction/replacement wipe `sk_c2t` and the sealer, then call `on_close(info,
reason)`; `on_close` exceptions are swallowed. `expire_idle` closes sessions with `now − last_activity ≥
idle_timeout_s`. A sealer is "fresh" iff nothing was sealed. `SessionTable.__init__` raises `ValueError` if
`evict_min_idle_s > idle_timeout_s` or any value < 1.

## Acceptance criteria (each becomes a test, in this order)
1. Given a fresh sealer, then `seal_open_result` uses nonce 0 (decrypt in the test with `AESGCM` and
   `_nonce(0)`); a second call → `USED`; `seal_frame_result` before it → `USED`.
2. Given `AESGCM.encrypt` patched to raise inside `seal_open_result`, then a retry → `USED` (nonce 0 burned).
3. Given frame results, then seqs are 1, 2, 3… and decrypt with `_nonce(seq)`; with the counter forced (private
   attribute in the test) to `MAX_SEQ + 1`, then `EXHAUSTED`.
4. (R-5 property test, hypothesis, ≥ 1 000 seals) Given random interleavings of `seal_frame_result`, injected
   encrypt exceptions and "publish failures" (the test re-sends stored bytes), then every `(key, nonce)` passed to
   AES-GCM (spy) is unique and the counter never decreases; a re-send is byte-identical to the first bytes.
5. Given `open_c2t` with seq 0, then 0 again, then −1/below, then a gap (5), then 5 again, then results are ok,
   `SEQ_REJECTED`, `SEQ_REJECTED`, ok, `SEQ_REJECTED`; an AEAD failure → `AUTH_FAILED` and `last_activity`
   unchanged; a wrong session id → `AUTH_FAILED`.
6. Given `open_frame(key, last_seq, …)`, then the same rules as criterion 5 for a free-standing key.
7. Given `_nonce(seq)`, then `b"\x00"*4 + u64be(seq)`; `seq` −1 and 2^53 → `ValueError("SEQ_RANGE")`.
8. (API surface) Given every public function and method in `teecustody.channel`, and every method of
   `T2cSealer`, `Session` and `SessionTable`, then no parameter is named `seq` or `nonce`.
   - Class constructors are checked too, except those in the exact allow-list `{FrameAad}`, a constant in the
     test (INC-2-API §4.9, 2026-10-13): codec wire records that hold AAD values and perform no encryption.
   - A deliberately added test-local class whose `__init__` takes `seq` must fail the check, which proves the
     allow-list is exact.
   - Only `T2cSealer.__init__`, `SessionTable.create` and `open_frame` take a key.
   - `_nonce` is not in `teecustody.channel.__all__`.
9. Given `create` for a principal with a live session, then the old one closes with `REPLACED` and its keys wipe.
10. (R-8) Given a full table and one session idle ≥ `evict_min_idle_s`, then `create` evicts exactly it
    (`EVICTED`, keys wiped, `on_close` called); with all sessions active → `OverflowError("SESSIONS_FULL")` and
    none evicted; equal `last_activity` → smallest `session_id` evicted; a rejected or unauthenticated frame never
    refreshes `last_activity`; at most one eviction per `create`.
11. Given `create` with a used sealer, then `ValueError("T2C_USED")` and the caller still holds the sealer.
12. Given `expire_idle` and `close_all`, then `IDLE_TIMEOUT` / `SHUTDOWN` reasons and every key wiped.
