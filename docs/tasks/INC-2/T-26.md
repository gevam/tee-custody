## Goal
A platform-agnostic client opens an attested HPKE session to a verified bundle, exchanges framed requests
over an untrusted queue, ignores everything it cannot authenticate, and can never reuse a c2t nonce. One task
owns the three files because `Session`, the open flow and the shared poll loop are one internal unit.

## Interface contract
INC-2-API §7.4 and §7.5 verbatim (`Clock`, `ChannelLimits`, `ChannelClientConfig`, `OpenPayload`,
`OpenOutcome`, `ChannelClient`, `Session`, the `fetchVerifiedBundles`/`open` steps (1)–(7), "Nonce discipline,
client side", `Session.request` rules, error mapping) and API-TL §3 (`openT2cFrame`, `readOpenResult`,
`readFrameResult`, `Session` constructor token). Normative extracts:
> The one private sealing method `#sealNext(op, payloadBytes)` reads `seq = nextC2tSeq` and **assigns
> `nextC2tSeq = seq + 1` synchronously, before its first `await`**. … Nothing ever decrements, resets or restores
> `nextC2tSeq` … `request()` never re-seals. It never auto-retries … No exported or internal function takes a
> `seq`, nonce or key for sealing. The nonce builder is module-private.
> `enroll`: `client_id = hexEncode(randomBytes(16))`, a fresh CSPRNG reply route for this call only, never stored
> or reused (R-4).
> `open` (1) `bundle` given → `isVerifiedBundle` and `isVerifiedAttestation(bundle.attestation)` else
> `UNVERIFIED_BUNDLE`.

Key reads (A2, INC-2-API §7.1 "Consumers"):
- `open` reads `bundle.identityPublicKey` exactly once into a local, used for `H(IK_pub)` and `info`.
- It reads the selected pre-key's `publicKey` exactly once into a local, used for `setupHpkeSender`.
- It uses only those locals.

Decisions: the constructor validates every `ChannelLimits` value as a positive safe integer and the presence
of each config capability (`TypeError("INVALID_CONFIG")`). Poll loop: one per route per `ChannelClient`; it calls
`transport.getResponses(route, cursor)`, advances the cursor, dispatches each body to every pending waiter on that
route (`readOpenResult`/`readFrameResult`), discards unmatched bodies, sleeps `pollIntervalMs` via `clock.sleep`
between polls, and stops when the route has no waiter. Transport errors during polling are retried until the
waiter's `responseTimeoutMs` expires (`TIMEOUT`). Timeouts measure `clock.now()`. Keys are zeroed (`fill(0)`) on
close, on failure and on timeout. `close()` seals op `"close"` with payload `null`, waits for its result up to
`responseTimeoutMs`, and destroys keys in `finally`; `request()` after close → `SESSION_CLOSED`. Remote error
strings outside `RemoteErrorCode` map to `"UNKNOWN"`. `selectPreKey` uses this client's used-id set per instance.

## Acceptance criteria (each becomes a test, in this order; `testChannelCrypto()` fake HPKE, a fake `Transport`
whose test-side "workload" decrypts and answers, fake `Clock`)
1. Given `open({op:"open_session",…})`, then the request AAD carries `payload.clientId`, the sealed plaintext
   decodes to the CDDL open-session payload, `payload.cs` and the plaintext buffer are zeroed after sealing, the
   `open_result` is accepted, and `session.clientId`/`sessionId`/`instanceId` are set.
2. Given two `enroll`s, then the AAD `client_id`s differ, match `^[0-9a-f]{32}$`, and come from
   `randomBytes(16)` (spy); `session.clientId` is the result payload's `client_id`; a payload without a valid
   `client_id` → `INVALID_RESPONSE` (R-4).
3. Given a structurally identical unbranded bundle or a bundle whose `attestation` is unbranded, then
   `UNVERIFIED_BUNDLE` (B-13); a bundle older than `bundleMaxAgeMs` triggers a re-fetch (the mocked
   `verifyBundle` is called again).
4. Given the mocked `verifyBundle` rejecting for every published bundle, then `NO_VERIFIED_BUNDLE`; given every
   pre-key used, `NO_USABLE_PREKEY`.
5. Given `postRequest` rejecting with `CapabilityError("UNAVAILABLE")`, then `ChannelError("TRANSPORT")` with
   `detail` `UNAVAILABLE`, the pre-key stays used and nothing is re-sealed.
6. Given responses with garbage bytes, another `request_id`, a bit-flipped ct, and 1 000 such bodies before the
   real one (SR-4 victim flood), then they are ignored and the open succeeds; given an authenticated R-3 violation,
   then `INVALID_RESPONSE`; given `ok:false`, then `REMOTE_ERROR` with the mapped `detail`; no response → `TIMEOUT`.
7. Given `request("test.echo", v)`, then the frame AAD `seq` is 0, then 1…; results must match session, op, a t2c
   seq above the last and `re`; mismatches are ignored; `op` `"close"`/pattern failure, oversized payload, more
   than `maxInFlight` pending → `INVALID_ARGUMENT`; the next seq above `MAX_SEQ` → `SEQUENCE_EXHAUSTED`.
8. (R-5 property, ≥ 1 000 seals) Given `aeadSpy`, random `postRequest`/`aes256GcmEncrypt` rejections, timeouts,
   host retries and up to `maxInFlight` concurrent `request()` calls, then every `(key, nonce)` is unique and the
   seq sequence never decreases.
9. (API surface) Given `index.ts` exports and the exports of `open.ts`/`session.ts`/`client.ts`, then no function
   has a parameter named `seq` or `nonce`, nothing named `*nonce*` is exported, and `Session.prototype.request.length
   === 2`.
10. Given `close()` with a failing transport, then keys are zeroed and `closed` is true; a second `close()` is a
    no-op.
11. Given `openT2cFrame`, `readOpenResult`, `readFrameResult`, then each API-TL §3 rule holds (one case per rule).
12. Given a crypto adapter rejecting `UNSUPPORTED`, then `CRYPTO_UNAVAILABLE` with that `detail`.
13. (A2, §7.2) Given a host that mutates its read copy of `bundle.prekeys[k].publicKey` (and of
    `bundle.identityPublicKey`) before `open`, then the `setupHpkeSender` spy receives the original key and
    `info` is built from the original `IK_pub`. A getter spy shows each field read exactly once per `open`.
