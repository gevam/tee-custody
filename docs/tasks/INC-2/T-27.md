## Interface contract
INC-2-API §9.2 verbatim:
```
node tools/scan-bundle.mjs --entry <path/to/src/index.ts> [--entry …] [--alias @teecustody/core=packages/teecustody-core/src/index.ts]
```
> Bundles each entry with esbuild (`bundle: true, format: "esm", platform: "browser", minify: false,
> legalComments: "none"`), so bundled dependencies (`@hpke/core` and its dependencies) are scanned. It fails on
> `/\beval\s*\(/`, `/\bnew\s+Function\b/`, `/(?<![.\w$])Function\s*\(/`, `/\bimport\s*\(\s*(?!["'`])/`, and
> `/\bset(?:Timeout|Interval)\s*\(\s*["'`]/`. Output: one line per hit, `<pattern-id>\t<entry>\t<byte offset>`, no
> source text. Exit codes: 0 clean, 1 hits, 2 usage/build error. Both packages' `lint` scripts call it.

Decisions: pattern ids `eval`, `new-function`, `function-call`, `dynamic-import`, `string-timer`; paths are
resolved relative to the current working directory; esbuild runs in memory (`write: false`, `metafile: true`); an
unresolved import or a Node built-in in the browser bundle is a build error (exit 2, C7).

Metafile checks (ADR 0011 C7a.1, C3a.1; INC-2-API §9.2, §16.5). They run on every entry after the regex scan.
They are exported as `checkMetafile(metafile, entry)` so the JSON fixtures can test them without esbuild.
- **C7a.1 (exit 2), as ruled in D-051 (a): defined on the bundle output.**
  - The `metafile.outputs[…].imports` entries with `external: true` must be exactly:
    - for the web scan (an entry whose inputs include `node_modules/@hpke/common/`): one entry, `path: "crypto"`,
      `kind: "dynamic-import"`;
    - for every other entry (the Core scan, fixtures): none.

    Any other output external → `external-import\t<entry>\t<path>`. A count other than one for the web scan →
    `external-allowance\t<entry>\t<count>`.
  - Per-input `imports` are used only for attribution. In the web scan, the input entries with `external: true`
    must be exactly 3, all `path: "crypto"`, `kind: "dynamic-import"`: one in
    `node_modules/@hpke/common/esm/src/algorithm.js` and two in `node_modules/@hpke/common/esm/src/utils/misc.js`.
    Any difference (another importer, another count, path or kind) → `external-attribution\t<entry>\t<input>`.
  - The constant is `HPKE_CRYPTO_EXTERNALS = { output: { path: "crypto", kind: "dynamic-import", count: 1 },
    inputs: { "node_modules/@hpke/common/esm/src/algorithm.js": 1, "node_modules/@hpke/common/esm/src/utils/misc.js": 2 } }`,
    with the comment "ADR 0011 C7a.1, D-045, D-051 (a)".
- **C7a.2.** `guarded-import.js` is exactly `try { await import("fs") } catch {}`. It must exit 2 through the
  C7a.1 metafile check: esbuild records the guarded import as `{path: "fs", kind: "dynamic-import", external:
  true}` (verified with esbuild 0.28.2), so the output is `external-import\t<entry>\tfs`. Do not set
  `logOverride` or rely on any esbuild log message for this case.
- **C3a.1 (exit 1, one line per violation).**
  - Any input matching `node_modules/@hpke/common/esm/src/curve/` with `bytesInOutput > 0` →
    `hpke-curve-bytes\t<entry>\t<input>`.
  - Any `@hpke/*` input not in `HPKE_INPUT_ALLOWLIST` with `bytesInOutput > 0` → `hpke-input-unlisted`.
  - Any capped input above its cap → `hpke-fragment-grew`.

  `HPKE_INPUT_ALLOWLIST` (path suffix → maximum `bytesInOutput`, or `null` for no cap) is copied verbatim from
  T-17's signed C6 follow-up item 4 (D-051), under D-051 condition 2:
  - it lists only inputs whose recorded `bytesInOutput` is greater than 0;
  - every input under `node_modules/@hpke/common/esm/src/hash/` carries its recorded size as its cap;
  - other inputs are `null`.

  A comment cites ADR 0011 C3a.1 and D-051, and says that a version change resets the list. A unit test asserts
  the two rules over the constant itself.
- **`profile-input` (exit 1).** Any input under `packages/teecustody-web/src/profile/` →
  `profile-input\t<entry>\t<input>` (§16.5 D4).
- No line ever contains source text.

C3a.2 semgrep rules (exact; verified with semgrep 1.178.0):
```yaml

    paths:

    message: webcrypto.ts imports only CipherSuite, DhkemX25519HkdfSha256, HkdfSha256, Aes256Gcm and error classes from @hpke/core (ADR 0011 C3a.2).

      include: ["/packages/teecustody-web/src/crypto/webcrypto.ts"]
    pattern-either:
      - pattern-regex: \bimport\s*\{[^}]*?(?<![\w$])(?!(?:CipherSuite|DhkemX25519HkdfSha256|HkdfSha256|Aes256Gcm|[A-Za-z]+Error)(?![\w$]))[A-Za-z_$][\w$]*[^}]*\}\s*from\s*["'`]@hpke/core["'`]
      - pattern-regex: \bimport\s+(?:type\s+)?(?:\*|[A-Za-z_$][\w$]*)[^;'"`]*?from\s*["'`]@hpke/core["'`]
      - pattern-regex: \bexport\b[^;]*?\bfrom\s*["'`]@hpke/core["'`]
      - pattern-regex: \bimport\s*\(\s*["'`]@hpke/core["'`]
```
The fixtures must:
- fire on `@hpke/common` in single, double and back quotes, including a deep path;
- fire on an unlisted name, an alias (`as`), a namespace or default import, a re-export, `type` names, and
  `import("@hpke/core")` in all three quote styles (A2);
- pass the four allowed names together with `*Error` names, on one line and across several lines. Scripts: core `lint` =
`eslint . && prettier --check . && node ../../tools/scan-bundle.mjs --entry src/index.ts`; web `lint` =
`eslint . && prettier --check . && node ../../tools/scan-bundle.mjs --entry src/index.ts --alias
@teecustody/core=../teecustody-core/src/index.ts`. The scanner's own unit test runs with Node's test runner:
the core `lint` script additionally ends with `&& node --test ../../tools/scan-bundle.test.mjs`, so it runs in
`lint_command`.

T-05 Security Review round 2 Lows (A4; ADR 0011 C5, SR-14):
- `tc-py-no-hpke-seams` gains `$S.create_sender_context(..., *$ARGS, ...)` and
  `$S.create_recipient_context(..., *$ARGS, ...)`, plus the A6 `.kem` pair (Tech Lead ruling below).
- **A6 ruling on `.kem`.** Keep the rule on `channel/hpke.py`, and allow exactly one KEM method there. A path
  exclusion would let `hpke.py`, the one module that holds pyhpke, call `decap` or any other KEM seam. The
  engineer's `pattern-not-inside: $S.kem.deserialize_private_key(...)` hides a seam nested in its argument
  (verified). Instead, add exactly these two entries under the rule's `pattern-either`:
  ```yaml
      - patterns:
          - pattern: $S.kem.$M(...)
          - metavariable-regex:
              metavariable: $M
              regex: ^(?!deserialize_private_key$)
      - patterns:
          - pattern: $S.kem
          - pattern-not-inside: $S.kem.$M(...)
  ```
  The Tech Lead verified with semgrep 1.178.0:
  - `_SUITE.kem.deserialize_private_key(sk.reveal())` is `ok`;
  - these fire: `_SUITE.kem.decap(enc, skr, pks)`, `k = _SUITE.kem`, `getattr(_SUITE.kem, "decap")`,
    `y = _SUITE.kem.deserialize_private_key` (not called), and a `decap` nested inside the
    `deserialize_private_key` argument.

  Use these as the fixture cases. `hpke.py:67` on main stays clean.
  - The last one bans low-level KEM access such as `suite.kem.decap(enc, skr, pks)` anywhere in the rule's
    scope (`packages/teecustody-py/src/**`, `examples/**`), and that scope includes `channel/hpke.py`.
  - The Tech Lead verified all three with semgrep 1.178.0.
  - `pos` adds: `create_sender_context(*args)`, `create_recipient_context(enc, *rest)`,
    `suite.kem.decap(enc, skr, pks)` and `k = SUITE.kem`.
  - `neg` adds `x = kem_id`.
- New rule `tc-ts-no-escaped-specifier`. It bans any backslash escape in a module specifier in Core and Web
  `src/**`, with no exclusion: `webcrypto.ts` is covered too, so `"\x40hpke/common"` cannot pass C3a.2 there.
  ```yaml
  - id: tc-ts-no-escaped-specifier
    message: Module specifiers are plain literals; escapes hide banned packages (ADR 0011 C3a.2, SR-14).
    severity: ERROR
    languages: [regex]
    paths:
      include: ["/packages/teecustody-core/src/**", "/packages/teecustody-web/src/**"]
    pattern-regex: (?:\bfrom|\bimport\s*\(?|\brequire\s*\()(?:\s|/\*(?:[^*]|\*(?!/))*\*/|//[^\n]*)*(["'`])[^"'`\n]*\\
  ```
  - The Tech Lead verified it with semgrep 1.178.0.
  - `pos`: `"\x40hpke/core"`, `"\u0040hpke/core"`, `"\u{40}hpke/core"`, `require("@\x68pke/core")`, and
    `import(/* c */ '\x40hpke/common')`.
  - `neg`: `"@teecustody/core"`, `"./wire/cbor.js"`, and a non-specifier string `"a\\b"`.
  - The probe `CASES` gains `("tc-ts-no-escaped-specifier", "ts", "packages/teecustody-web/src/crypto", True)`.

## Acceptance criteria (each becomes a test in `scan-bundle.test.mjs`, in this order)
1. Given `clean.js`, then exit 0 and no output.
2. Given each violating fixture, then exit 1 and exactly one line `<pattern-id>\t<entry>\t<offset>` for its
   pattern, with no fixture source text in stdout or stderr.
3. Given a fixture containing only `x.Function(1)` and `evaluate(1)`, then exit 0 (the `(?<![.\w$])` and `\b`
   guards); given a fixture containing `setTimeout(fn, 1)`, then exit 0; `setTimeout("x", 1)` → `string-timer`.
4. Given a missing `--entry`, an unknown flag or a non-existent file, then exit 2.
5. Given an entry importing `node:fs` with `platform: "browser"`, then exit 2.
6. Given the real packages, then the core and web `lint` scripts exit 0. Web includes `@hpke/core`, and the one
   C7a.1 allowance matches exactly once.
7. (C7a.2) Given `guarded-import.js`, then exit 2 with exactly the line `external-import\t<entry>\tfs`, and with no
   `logOverride` in the esbuild options (assert the options object).
8. (C7a.1, D-051 a) Given `meta-extra-external.json` (a second output external), `meta-allowance-unused.json`
   (a web scan with no output external), `meta-allowance-twice.json` (two output externals) and
   `meta-attribution-mismatch.json` (`utils/misc.js` ×1, plus an `algorithm.js` external with kind `import`), then
