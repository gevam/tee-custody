> 3. `sk = prekeys.take(id)`; `try: open_base(...) finally: sk.wipe()` ⇒ failure `OPEN_FAILED`. On success,
> `sealer = T2cSealer(opened.sk_t2c)` immediately. From here on, every exit path seals exactly one `open_result`
> with `sealer` (D2-16).
> 6. Hold `reply_route = aad.client_id` in a local only. Build the request with `claimed_client_id =
> aad.client_id` for `open_session`, or `None` for `enroll` (R-4).
> 7. Response route: `OutboundResponse(client_id=reply_route, ...)`, the only use of `reply_route`.

Decisions: `ProcessResult.outcome` = the `AggregateOutcome` value for counted failures (responded or not) and
the `ChannelOutcome` value otherwise; an authenticated frame whose payload fails `payload_decode` is answered
`{re, ok:false, error:"INVALID_FRAME"}` with outcome `FRAME_ACCEPTED` and no count; `op == "close"` gives
outcome `SESSION_CLOSED`. Rejected opens without a session use `OpenResultAad(session_id=None, …)` sealed by the
fresh `sealer`. Opener/handler exceptions → `BACKEND_UNAVAILABLE` (§4.8); for the opener this is
`OpenRejected(BACKEND_UNAVAILABLE)` counted as `OPEN_REJECTED`. Every `Secret` created in `process` is wiped
on every path. Times: `now = clock()`; skew check `abs(now − timestamp) > request_skew_s` ⇒ stale.

Decisions A1:
- `sessions.create` raising `ValueError("SESSION_ID_IN_USE")` (after the opener accepted) is handled like the §4.10
  step-6 principal-mismatch path: `opener.closed(OPEN_ABORTED)`, wipe `sk_c2t`, count `OPEN_REJECTED`, and
  respond `INTERNAL` with `OpenResultAad(session_id=None, …)` sealed once by the still-fresh `sealer`.
- `Session.open_c2t` always receives the `FrameAad` decoded from the frame's own `aad_bytes`, never one built
  separately. So the T-23 `SEQ_REJECTED` range guard is unreachable from the wire.
- `SessionReject(AUTH_FAILED)`, including the empty-plaintext case of T-23 A1, counts `FRAME_AUTH_FAILED`, with
  no response and no handler call.

## Acceptance criteria (each becomes a test, in this order; real `PreKeyStore`, `SessionTable`, `ReplayCache`,
fake `AuditEmitter`/opener/handler in `support_server.py`, client side sealed with `pyhpke` in tests)
1. Given a valid `open_session`, then `SESSION_OPENED`, the response routes to the AAD client id, decrypts with
   `sk_t2c`/nonce 0 to `{ok:true,payload}`, a session exists for the opener's principal, the log line has only
   allow-listed fields.
2. Given each pre-HPKE failure (oversize, invalid, wrong instance, unknown/consumed pre-key, stale both
   directions, replayed), then the §10 code is counted once, `response is None`, `open_base` is never called
   (spy), and no pre-key is consumed except by the replayed message's first, successful use.
3. Given HPKE failure (any one-byte AAD change that still decodes; an envelope sealed for another instance
   whose `instance_id`/`prekey_id` were rewritten to this one's, §13.3; wrong info), then `OPEN_FAILED` counted,
   no response, the pre-key is consumed and its `Secret` wiped.
4. Given an invalid open payload, then `OPEN_PAYLOAD_INVALID` counted and an encrypted `INVALID_FRAME` response.
5. (R-4, SR-14) Given an `enroll` whose AAD client id equals a live client's id and an opener minting a new
   principal, then the opener saw `claimed_client_id is None`, the live session is not `REPLACED`, the response
   goes to the AAD route only, and the log/audit fields name only the minted principal.
6. (R-4) Given an opener returning a principal ≠ the claim, or an enroll principal failing `CLIENT_ID_PATTERN`,
   then no session, `opener.closed(…, OPEN_ABORTED)`, `OPEN_REJECTED` counted, response `{ok:false,
   error:"INTERNAL"}` with nil session id.
7. Given a rejected open, then `{ok:false, error}` with nil session id; an opener exception → `BACKEND_UNAVAILABLE`
   with no exception text anywhere (SR-11).
8. Given a full replay cache, then `CHANNEL_LIMIT_EXCEEDED` and `LIMIT_EXCEEDED` response; a full session table
   with no evictable session, then the same plus `opener.closed(OPEN_ABORTED)`.
9. Given frames: unknown session, seq reuse, seq backwards, AEAD failure, then `SESSION_UNKNOWN`,
   `FRAME_SEQ_REJECTED` ×2, `FRAME_AUTH_FAILED`, no response, handler not called; a valid frame → handler called
   once, response `re == seq`, t2c seq 1, 2…; `close` → ok then session closed; payload > 32 768 → `LIMIT_EXCEEDED`.
10. (R-5) Given any path after `open_base` succeeds (including injected exceptions in the opener, `create` and
    encoding), then exactly one `seal_open_result` call occurs (spy).
11. (§13.3 forward secrecy) Given a captured transcript replayed into a fresh `ChannelServer` with the same
    `IdentityKey` after `close`, then `PREKEY_UNKNOWN`/`OPEN_FAILED` and the stores hold no key for it.
12. Given a seeded fuzz of 2 000 mutated envelopes, then `process` never raises and each call < 50 ms.
13. (A1) Given `rng` forced to return an existing session's id, then the opener sees `closed(OPEN_ABORTED)`, the
    response is `INTERNAL` with a nil session id, `seal_open_result` is called exactly once, `OPEN_REJECTED` is
    counted, and the existing session is untouched.
14. (A1) Given an authenticated c2t frame with empty plaintext, then `FRAME_AUTH_FAILED` is counted, there is no
    response, and the handler is not called.
