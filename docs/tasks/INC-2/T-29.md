## Goal
One object boots the workload (identity key, attested token, own digest, pre-keys, bundle), then pulls,
processes, responds and maintains state on a schedule — never opening a listener, never hammering the
launcher or queue, and wiping every key at shutdown.

## Interface contract
INC-2-API §4.13 verbatim (`StopCode`, `WorkloadStopped`, `TickReport`, `RunLoop` signature, `tick` order
(1)–(7), the B-08 rule, queue-unavailable rule) plus §4.11 ack/re-publish rules and API-TL TL-2, TL-3:
> `tick` order: (1) attestation refresh **only if `clock() >= next_refresh_attempt_at`** (B-08); (2)
> `prekeys.expire()`, `top_up()`; (3) republish the bundle if the token was refreshed or the pre-key set changed,
> at most once per `bundle_republish_min_interval_s`; (4) `pull_requests` → `process` → `publish_response` → `ack`;
> (5) `sessions.expire_idle()`; (6) pre-key burn check at interval end; (7) `audit.tick()`.
> **B-08 rule.** After `FAILED_KEPT_CURRENT`, `next_refresh_attempt_at = now + min(retry_max, retry_min × 2^(n−1))`
> for the n-th consecutive failure; a `REFRESHED` outcome resets n.

Decisions: `instance_id = rng(16).hex()` in `__init__`; `__init__` raises
`ConfigError(INVALID_LIMITS, "session_evict_min_idle_s")` if it exceeds `params.idle_timeout_s`. `start()`
builds `IdentityKey.generate()`, `AttestationLifecycle(launcher, audience=…, token_type=…,
identity_public_key=ik.public_bytes(), refresh_margin_s=params.refresh_margin_s, clock=clock, logger=logger)`,
`own_image_digest(token, max_token_bytes=limits.max_token_bytes)`, `PreKeyStore`, `AuditEmitter`,
`ReplayCache`, `SessionTable` (with the TL-2 `on_close`), `ChannelServer`, then `top_up()` and publishes with
TL-3 `expires_at`. A refreshed token with a different digest → `shutdown()` then
`WorkloadStopped(DIGEST_CHANGED)`. Pull failures use the same backoff formula with their own counter; 10
consecutive → `shutdown()` then `WorkloadStopped(QUEUE_UNAVAILABLE)`. `publish_response` failure: log
`RESPONSE_PUBLISH_FAILED`, retry once with the identical `body` object, then `ack` regardless. `run(stop)`: when a
tick skipped pulling (backoff), it waits `stop.wait(min(pull_wait_s, next_pull_at − clock()))`.
`PreKeyStore` raising `PREKEY_IDS_EXHAUSTED` → `shutdown()` then `WorkloadStopped(PREKEY_IDS_EXHAUSTED)`.
Burn interval = `audit_aggregate_interval_s`; alert interval in ms. `shutdown()` is idempotent. Unit tests
replace `ChannelServer` in this module with a fake via `monkeypatch` (the real server is T-28, same wave).

Decisions A1:
- **Expiry first (SR Medium).** Step (1) begins, before the B-08 gate, with: if
  `clock() >= lifecycle.current().expires_at`, then `shutdown()` and raise `WorkloadStopped(ATTESTATION_EXPIRED)`.
  No request is processed and no bundle is republished after expiry, whatever the backoff state.
- **B-08 cap.** After `FAILED_KEPT_CURRENT`,
  `next_refresh_attempt_at = max(now, min(now + min(retry_max, retry_min × 2^(n−1)), expires_at − 1.0))`. The
  last retry therefore lands before expiry.
- **Misuse guards (CR ruling 4, D-053 precedent).** `tick()` before `start()`, or after `shutdown()`, raises
  `RuntimeError("NOT_STARTED")`. `start()` called a second time on the same instance, including after
  `shutdown()`, raises `RuntimeError("ALREADY_STARTED")`, and live state is untouched. Instances are
  single-use, and nothing is silently replaced or wiped.
- **Queue errors (CR feedback).** `QueueError(UNAVAILABLE)` from any of `pull_requests`, `publish_response`,
  `ack` or `publish_bundle` adds to the one consecutive-failure counter and ends the tick's queue work. It
  uses the same backoff. A message that was not acked is redelivered, and a republish that was due stays due.
  The 10th consecutive failure → `shutdown()` and `WorkloadStopped(QUEUE_UNAVAILABLE)`. Any other `QueueError`
  code → `shutdown()` and `WorkloadStopped(QUEUE_UNAVAILABLE)` at once. A raw `QueueError` never escapes `tick`.
- **Step order (SR Low).** `sessions.expire_idle()` runs before `pull_requests`. The order becomes: (1) expiry
  check and refresh, (2) pre-keys, (3) republish, (4) `expire_idle`, (5) pull/process/publish/ack, (6) burn
  check, (7) `audit.tick()`. A session idle past its timeout at the start of a tick can no longer process a
  frame.

Decisions A2 (final fix round):
- **CM1, expiry re-check (Medium).** Use one private helper that does the A1 step (1) expiry check. It reads
  `clock()` afresh, and if `clock() >= lifecycle.current().expires_at` it calls `shutdown()` and raises
  `WorkloadStopped(ATTESTATION_EXPIRED)`. `tick` calls it at step (1), immediately before every `publish_bundle`
  in step (3), and immediately before every `server.process` call in step (5). It is called per message, so the
  first check after a pull that blocked across expiry is the one before the first message. On expiry, the
  current message and every remaining pulled message are not processed, answered or acked. They stay with the
  adapter's ack deadline and retention (§4.11). Nothing is withdrawn per message, and no error response is
  sealed, because sealing would process the request after expiry. The `withdraw_bundle` in `shutdown()` is the
  only queue effect. A message whose `process` began before `expires_at` is answered and acked as usual,
  including the one publish retry. `start()` does not re-check, because its token is fresh.
- **SL2, last-second retry (Low).** After `FAILED_KEPT_CURRENT` at `now`, compute
  `c = min(now + min(retry_max, retry_min × 2^(n−1)), expires_at − 1.0)`. Then set
  `next_refresh_attempt_at = c` if `c > now`, otherwise `expires_at`. The capped retry at `expires_at − 1.0`
  is still made once. Once it fails, no launcher call is made before the expiry stop. This replaces the A1
  formula `max(now, …)`.
- **SL1, no hanging tests (Low).** No new dependency, so no `pytest-timeout`. Every test that calls `run()` passes
  a stop event that raises `AssertionError("TICK_BUDGET_EXCEEDED")` from `is_set()` once it has been checked more
  than a fixed budget. The budget is at most 50, and at least the test's expected tick count. No test passes
  a plain `threading.Event()` to `run()`. Every loop in a test over `tick()` has a fixed upper bound.
- **CL1, exception precedence in `run` (Low).** If `start()` or `tick()` raises, `run` calls `shutdown()`,
  suppresses a `QueueError` from it, and re-raises the original exception object unchanged. When `run` ends
  because `stop` is set, a `QueueError` from `shutdown()` becomes `WorkloadStopped(QUEUE_UNAVAILABLE)` raised
  `from` that error, not `from None`. A raw `QueueError` still never escapes `run`.

## Acceptance criteria (each becomes a test, in this order; fake launcher, fake clock, fake `WorkloadQueue`)
1. Given `start()`, then the launcher was asked with `identity_nonce(ik.public_bytes())`, one bundle was published
   for `instance_id` whose `decode_bundle` IK matches and whose pre-key signatures verify over the token's digest,
   with TL-3 `expires_at`.
2. (B-08, SR-4) Given a launcher that fails every refresh, then 1 000 `tick()` calls within `retry_min` make
   exactly one launcher call; successive failures wait `retry_min`, 2×, 4× … capped at `retry_max`; a success
   resets the delay.
3. Given the lifecycle raising on an expired token, then `shutdown()` ran and `WorkloadStopped(ATTESTATION_EXPIRED)`.
4. Given a refreshed token with another digest, then `WorkloadStopped(DIGEST_CHANGED)` after shutdown.
5. Given pulled messages, then each is processed, its response published to `OutboundResponse.client_id`, and
   acked; given `publish_response` failing once, then one retry with the identical bytes object, then ack;
   failing twice, then ack and `RESPONSE_PUBLISH_FAILED` logged.
6. Given 10 consecutive pull `UNAVAILABLE`, then `WorkloadStopped(QUEUE_UNAVAILABLE)`; fewer recover.
7. Given consumption above `prekey_burn_alert_threshold` in one interval, then exactly one `PREKEY_BURN_HIGH`
   alert with that interval; below it, none.
8. Given pre-key changes, then republish happens at most once per `bundle_republish_min_interval_s`.
9. (NFR-2) Given `socket.socket.bind` and `listen` patched to fail the test, then `start()` and 5 `tick()`s run
   against the simulator launcher and an in-memory fake queue without calling them.
10. Given `shutdown()`, then `withdraw_bundle`, `close_all(SHUTDOWN)` (on_close logs `SESSION_CLOSED`),
    `destroy_all`, `audit.close()` each ran once, also on a second call (idempotent).

12. (A1, the SR PoC) Given the launcher failing on every refresh with the default backoff, then the first `tick` at

13. (A1) Given `tick()` before `start()` and after `shutdown()`, then `RuntimeError("NOT_STARTED")`. Given a
