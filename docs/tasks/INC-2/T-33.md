## Acceptance criteria (each becomes a test, in this order; INC-2-API §16.9 C1–C7)
1. (C1) Given a spy Fetcher, for `valid` and for each case that reaches key retrieval, then `get` is called
   exactly once with an argument `=== profile.jwks_uri`. No argument ever contains `openid-configuration`.
   For each header-rule failure, `get` is called zero times.
2. (C2, T-29) Given tokens minted with `signer: "attacker"`, once with header `kid` `"attacker-kid"` and once
   with `KID`, then `AttestationError("UNTRUSTED_SIGNER", "signature")`. Positive control: with a Fetcher
   mapping `profile.jwks_uri` to the attacker JWKS, the same tokens pass `checkSignature`.
3. (C3) Given each production and development `jwks_uri` variant in §16.9 C3, then
   `TrustProfileError("INVALID_PROFILE", "jwks_uri")`.
4. (C4) Given the exact INC-1 v1 JSON, then field `profile_version`. Given v2 plus `discovery_url`, then field
   `discovery_url`. Given v2 plus `jwks_origin`, then field `jwks_origin`. Given v2 without `jwks_uri`, then
   field `jwks_uri`.
5. (C5) Given Node 22, then `new URL(GOOGLE_JWKS_URI).href === GOOGLE_JWKS_URI`. Read the constant through a
   production profile that parses.
6. (C6) Given a redirect, a non-200 status, an oversize body, non-JSON or no `keys`, then `UNTRUSTED_SIGNER`.
   Given `maxDiscoveryBytes` absent, then it is accepted. Given `0`, then `MALFORMED` at `signature`.
7. (C7) Given `uvx semgrep==1.178.0 --test .semgrep/`, then both fixtures behave as stated, and trunk is clean.
8. Given the two contract tests, then every v1 or discovery assertion is replaced by its §16.9 C1–C4
   counterpart. The case count does not decrease.
