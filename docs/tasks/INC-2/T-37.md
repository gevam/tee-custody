`notes-gateway` member's runtime closure. Any other version, or any other path to h11, is still flagged.

## Interface contract
D-049 (`framework.yaml` `security.dependency_policy`): h11 is admitted past the 18-month rule only as uvicorn's
required dependency in `examples/notes-app/gateway`. It must be OSI-licensed, exactly locked and pip-audit clean.

Decisions (exact):
```python
# D-049 (human, 2026-10-13); DEBT-3, expires INC-5. Re-checked at every lock change.
AGE_EXCEPTIONS: Final = {
    "h11": AgeException(version="0.16.0", member="notes-gateway", via="uvicorn", decision="D-049"),
}
```
- `AgeException` is a frozen dataclass with those four `str` fields.
- `check_registry` skips `stale h11` if and only if all three of these hold:
  - (a) `uv.lock` resolves `h11` to exactly `0.16.0`;
  - (b) `h11` is in the runtime closure of the `notes-gateway` member;
  - (c) `h11` is **not** in the runtime closure of the shipped Python roots computed with the `via` package
    (`uvicorn`) removed from the graph. This means every path from any shipped root, the libraries
    `teecustody` and `teecustody-sim` included, passes through uvicorn, and uvicorn is reached only from the
    gateway.
- If any condition fails, the normal age check applies.
- The licence check and `pip-audit` are untouched. h11's licence is still checked.
- No other package gains an exception. The mechanism is not generic configuration: adding an entry needs a
  human decision record.

## Acceptance criteria (each becomes a test, in this order; `--today 2026-10-25`, recorded registry with h11 released 2025-04-24)
1. Given the clean tree plus a gateway member whose runtime graph is `notes-gateway → uvicorn → h11` (h11
   0.16.0), then no `stale h11`.
2. Given the same with h11 `0.15.0` (`h11-other-version`), then `VIOLATION stale h11`.
3. Given h11 0.16.0 also reached from `teecustody`'s runtime closure (`h11-library-closure`), then
   `VIOLATION stale h11`.
4. Given h11 0.16.0 as a direct runtime dependency of `notes-gateway`, not through uvicorn
   (`h11-direct-gateway`), then `VIOLATION stale h11`.
5. Given another stale runtime package in the gateway closure, then it is still reported.
6. Given h11 with a non-OSI licence in the recording, then `VIOLATION licence h11` (the exception covers age
   only).
