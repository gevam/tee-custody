## Goal
A client whose clock is up to 300 s behind Google's issuer accepts fresh tokens. `exp` and past-`iat` behaviour stay
exactly as they are. Tests pin the constant at ±1 ms, and they prove that verification reads `now` fresh on every call.

## Interface contract
Unchanged: `export function checkTime(t: ParsedToken, p: TrustProfile, nowMs: number): void; // §6.4`
(INC-1 API.md). Error codes, check id `time`, check order and exports are unchanged. Rule, verbatim from ADR 0013:

```ts
const CLOCK_SKEW_S = 300;                          // module-private; equals spec §14 REQUEST_SKEW default; MUST stay < 600
const CLOCK_SKEW_MS = CLOCK_SKEW_S * 1000;
// 1. exp:        !(exp * 1000 > nowMs)                                        → EXPIRED        (unchanged; no leeway)
// 2. iat past:   !(nowMs - iat * 1000 <= maxAgeMs)                            → EXPIRED        (unchanged)
// 3. iat future: !(iat * 1000 - nowMs <= Math.min(maxAgeMs, CLOCK_SKEW_MS))   → NOT_YET_VALID  (was maxAgeMs)
// 4. nbf:        nbf !== undefined && !(nbf * 1000 - nowMs <= CLOCK_SKEW_MS)  → NOT_YET_VALID  (was 0)
```

Keep `!Number.isFinite(maxAgeMs) ||` on step 2, and keep reading `nbf` after step 3. Nothing reads `profile_kind`.

## Acceptance criteria (in this order; "first red" is what fails on trunk)
Notation: `T(...)` = `checkTime(token({...}), PROFILE, nowMs)`; `E` = `exp: NOW_S + 3600`.
1. `{E, iat: NOW_S, nbf: NOW_S+300}` passes at `NOW_MS` and rejects `NOT_YET_VALID` at `NOW_MS−1`. First red: the pass.
2. `{E, iat: NOW_S+300}` passes at `NOW_MS` and rejects `NOT_YET_VALID` at `NOW_MS−1`. First red: the rejection.
3. With `brandTrustProfile({...PROFILE, token_max_age_s: 60})`:
   - `{E, iat: NOW_S+60}` passes at `NOW_MS` and rejects at `NOW_MS−1`;
   - `{E, iat: NOW_S, nbf: NOW_S+300}` passes at `NOW_MS`.
   First red: the `nbf` pass.
4. `{exp: NOW_S, iat: NOW_S−60}` passes at `NOW_MS−1` and rejects `EXPIRED` at `NOW_MS`, so `exp` has no leeway.
5. Order:
   - `{exp: NOW_S, iat: NOW_S, nbf: NOW_S+301}` → `EXPIRED`;
   - `{E, iat: NOW_S−3601, nbf: NOW_S+301}` → `EXPIRED`;
   - `{E, iat: NOW_S+301, nbf: "x"}` → `NOT_YET_VALID`. First red: on trunk this gives `CLAIM_MISMATCH`.
6. S4 repairs:
   - "iat exactly max age in the future" moves to the reject table (`NOT_YET_VALID`).
   - "nbf one second ahead (no skew)" moves to the pass table as "(within skew)".
   - "checks iat before nbf" and "checkTime ignores an inherited nbf" use `NOW_S + 301`.
7. The existing NaN/Infinity tests for `nowMs` and `token_max_age_s` stay unchanged and green.
8. The cases in criteria 1–3 give identical results under `profile_kind: "production"`.
9. `Object.keys(await import(claims.js)).sort()` equals the six current exports, so `CLOCK_SKEW_S` is not exported.
10. S1 (`verify.test.ts`). The clock is mutable, and the fetcher's `get` sets it to `EXP*1000` before delegating:
    - `verifyAttestation(mint())` rejects `time/EXPIRED`;
    - without the advance, it resolves.
    This proves `now` is read after the JWKS fetch, and the test never relies on `nbf`.
11. S1, with one `deps` object and one token:
    - it resolves at `NOW_MS`;
    - it rejects `time/EXPIRED` at `EXP*1000`;
    - it resolves again at `NOW_MS`.
    No `now` and no result is cached.
12. S1 (`clock-freshness.test.ts`):
    - Setup: `vi.mock` `verifyBundle`. The mock records `deps.now()` and returns `brandedBundle(fx, deps.now())`.
    - Setup: subclass `FakeWorkload` so that `listBundles` does `clock.t += 7_000`, records `clock.t`, then delegates.
    - Run: two `client.open(openSession())` calls, with `clock.t += 1_000` between them.
    - Assert: the verifier's values equal the recorded fetch values, both are present and they differ.
    - Assert: the first call's `deps.now()`, invoked afterwards, equals `clock.now()`.
