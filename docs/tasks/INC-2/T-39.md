## Goal
WebKit's transient X25519 `generateKey` failure (~0.35%/call) no longer fails `open` or poisons the adapter: the probe and the sender's ephemeral key get at most 3 native attempts, a failed probe is not cached, and exhaustion is `UNSUPPORTED`. FACTS.md describes the browsers CI actually runs (Playwright 1.63.0) and records the measured defect.

## Interface contract
INC-2-API §8.1 (unchanged signatures; this bullet text is on main, verbatim):
> `setupHpkeSender(pkR, info)` / `setupHpkeReceiver(skR, enc, info)`: … Key length ≠ 32 → `INVALID_ARGUMENT`; … X25519 key generation, meaning the probe and the sender's ephemeral key, is attempted at most 3 times (ADR 0011 C8). When the attempts are exhausted → `UNSUPPORTED`. Other sender failures are not retried → `INVALID_ARGUMENT`. A failed probe is not cached.

B-45 §5 (private, not exported, not an option):
```ts
/** ADR 0011 C8 (B-45): total attempts per X25519 key generation; WebKit's generateKey fails transiently. */
const X25519_KEYGEN_ATTEMPTS = 3;
/** Runs `attempt` up to X25519_KEYGEN_ATTEMPTS times; rethrows at once if `retryable(error)` is false. */
async function boundedKeygen<T>(attempt: () => Promise<T>, retryable: (error: unknown) => boolean): Promise<T>;
```
Decisions: the probe predicate is `() => true`; the sender predicate is `(e) => e instanceof NotSupportedError`. A synchronous throw from `attempt()` is treated as a rejection (QA's SR-14 proxy throws synchronously). Probe reset per R1: reset `suite` to `undefined` only if it still holds the failed promise. `deserializePublicKey` runs once, before and outside the retry; its failure → `INVALID_ARGUMENT`. Exhaustion → `new CapabilityError("UNSUPPORTED")`; every other sender failure → `new CapabilityError("INVALID_ARGUMENT")`; neither has a `cause`.
