## Interface contract (what to verify; INC-2-API §12, ADR 0011 C1–C7)
**V-2.3 `pyhpke`:** latest release and its date (≤ 18 months before today), OSI licence, exact version
chosen, sdist + wheel sha256 from PyPI, runtime `Requires-Dist` ⊆ {`cryptography`}, exporter API
(`export(exporter_context, length)` on sender and recipient contexts), C2 table (for X25519, HKDF-SHA256's
HMAC, AES-256-GCM: the native `cryptography`/OpenSSL call each delegates to, with source file and line),
C4 KATs: filtered sets (mode 0, kem 0x0020, kdf 0x0001, aead 0x0002) and (mode 0, kem 0x0020, kdf 0x0001,
aead 0x0001 = Appendix A.1) are each non-empty; DeriveKeyPair(ikmE/ikmR) → pkEm/pkRm, `enc`, every encryption
and every export match on the receiver side; all-zero `enc` fails. For information only: does
`cryptography==50.0.2` expose RFC 9180 Base mode with export for 0x0020/0x0001/0x0002 (C1)?

**V-2.4 `@hpke/core` (+ `@hpke/common`):** exact versions, npm `integrity` sha512 of each tarball, licence,
release dates, same repository and publisher, runtime closure ⊆ {`@hpke/core`, `@hpke/common`} (C3);
`DhkemX25519HkdfSha256` uses native WebCrypto X25519 with no bundled JS curve (C2 table with source lines);
C4 KATs in Node 22 on both sender (with `ekm` injection in the scratch test only) and receiver sides; an
esbuild `platform: "browser"` bundle of a file importing `CipherSuite`, `DhkemX25519HkdfSha256`,
`HkdfSha256`, `Aes256Gcm` builds with no unresolved Node built-in (C7) and has zero hits for the five
INC-2-API §9.2 regexes (run them in scratch).

**Amendment text** (append, in this order): a table per package (version, registry hash, licence, release
date, publisher, runtime closure); the C2 primitive-source tables; the C4 KAT result (case counts per filtered
set, pass/fail, `test-vectors.json` SHA-256); the C7/§9.2 result; the C1 informational line; a line
"Sign-off: pending Security Architect (scoped to C1–C5 evidence)".

## Acceptance criteria (each becomes a check recorded in the Task Report, in this order)
1. Given the scratch KAT runs, then each filtered set is non-empty and every check passes in both libraries;
   the counts are recorded.
2. Given PyPI/npm metadata, then every version, hash, licence and date in the amendment matches the registry
   (record the URLs).
3. Given `tests/fixtures/rfc9180/test-vectors.json`, then `sha256sum` equals the README value and the file
   is byte-identical to the source at the recorded commit.
4. Given the amendment, then it contains every item listed above and no other edit to the ADR exists
   (`git diff` shows additions only, below "Amendments").
