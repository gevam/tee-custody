## Goal
`docs/tasks/INC-2/FACTS.md` records, with sources and versions, which target browsers honour hash-only CSP
for SRI scripts, deliver WebAuthn PRF under Playwright, and have native WebCrypto Ed25519 and X25519; and
whether the Confidential Space OIDC endpoints allow browser (CORS) fetches. T-17, T-20, T-21 and T-32
read their pass conditions from this file.

## Interface contract (INC-2-API §12 and INCREMENTS V-2.2; rows and pass conditions verbatim)
| Id | Verify | Pass condition | If it fails |
|---|---|---|---|
| V-2.2 | Each target browser honours CSP `script-src` hash sources for an external script with a matching SRI `integrity` | Page whose CSP lists only the script's `sha384` hash loads it and nothing else | Record the browser as unsupported (fail closed). Never add `'self'`/host sources. If this excludes a browser the human expects, say so in the report (escalation) |
| V-2.5 | WebAuthn PRF under Playwright: Chromium CDP virtual authenticator with `hasPrf`; whether PRF results arrive at `create` or only at `get`; Firefox/WebKit behaviour | PRF obtainable in Chromium CI | Vault CI tests are Chromium-only; others assert fail-closed |
| V-2.6 | WebCrypto `Ed25519` verify and `X25519` deriveBits per target browser and Node 22 | Recorded per browser | Unsupported → `UNSUPPORTED` → fail closed, recorded |
| V-2.7 (new, CI-2-1) | Do `https://confidentialcomputing.googleapis.com/.well-known/openid-configuration` and its `jwks_uri` send `Access-Control-Allow-Origin` for a cross-origin GET (record the exact header values, `Vary`, and whether credentials are required) | Recorded with the date, the raw response headers (no bodies needed) and the request `Origin` used | If no CORS header: report CONTRACT_ISSUE (browser clients cannot fetch discovery/JWKS; Architect decision) |

`FACTS.md` format: one section per Id with a result table (`browser/runtime`, `version`, `result`,
`evidence`), the commands or minimal page used (inline, ≤ 30 lines each), and a final "Support matrix" table
(browser × {CSP hash SRI, PRF at create, PRF at get, Ed25519, X25519}) that T-32's spec reads.

## Acceptance criteria (each becomes a recorded check, in this order)
1. Given the pinned Playwright, then FACTS.md names its version and the three browser build versions.
2. Given V-2.2's minimal page (hash-only CSP, SRI external script, plus one un-hashed script), then each
   browser's result shows the hashed script ran and the other was blocked, or the browser is marked unsupported.
3. Given a Chromium CDP virtual authenticator `{protocol: "ctap2", transport: "internal",
   hasResidentKey: true, hasUserVerification: true, isUserVerified: true, hasPrf: true}`, then FACTS.md
   records whether `create` returns `prf.enabled === true` and `prf.results.first`, and whether `get` with
   `prf.eval.first` returns 32 bytes; same with `hasPrf: false`.
4. Given each browser and Node 22, then Ed25519 verify and X25519 deriveBits support are recorded.
5. Given V-2.7, then the raw response headers for both URLs are recorded.

## Security requirements
- SR-13 / NFR-5: every unsupported capability is recorded as fail-closed; no workaround is proposed that
  relaxes CSP, adds a JS curve, or falls back from PRF.
